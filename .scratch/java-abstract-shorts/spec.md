# 스펙: 자바 입문 열두 번째 — 추상 메소드와 추상 클래스

Status: ready-for-agent

## Problem Statement

자바 입문 시리즈를 따라온 시청자는 상속 편에서 부모 클래스 `Person`의 `hello()`를 자식 클래스 `Student`·`Teacher`가 오버라이딩하는 것을 배웠고, 지난 편에서는 `final`로 오버라이딩·상속을 *막는* 방법을 배웠다. 하지만 반대로 "자식에게 오버라이딩을 *강제하는*" 방법은 아직 모른다.

입문자는 특히 다음을 자주 헷갈린다.

- 몸체 없는 메소드를 왜 만드는지, 어떻게 쓰는지(`{ }` 대신 `;`)
- 추상 메소드가 있는데 클래스에 `abstract`를 안 붙이면 왜 오류인지
- 추상 클래스로 왜 `new`를 못 하는지
- 자식 클래스가 추상 메소드를 빠뜨리면 무슨 일이 생기는지, 해결 방법은 무엇인지
- 추상 클래스는 "아무것도 없는 틀"이라 필드·생성자도 못 갖는다는 오해

3분 이하 세로 쇼츠 한 편으로, 실제로 컴파일·실행되는 예제를 써서 이 개념들을 정확히 보여 줄 영상이 필요하다.

## Solution

시리즈 열두 번째 영상 "추상 메소드와 추상 클래스"를 기존 영상과 같은 디자인·제작 방식으로 만든다.

- 영상 규격: 1080×1920, 약 2분 30초, 1.2배 템포
- 예시 클래스: 상속 편의 `Person` → `Student`(민수·85) / `Teacher`(서준)를 그대로 이어 쓰고, `Person`을 추상 클래스로, `hello()`를 추상 메소드로 바꾼다.
- 흐름: 상속 편 코드의 아쉬운 점 → 추상 메소드 → 추상 클래스 → 자식이 완성 → 추상 클래스의 구성 → 주의

장면 구성은 아래와 같다.

| id | 장면 | 진행 표시 | 내용 |
|---|---|---|---|
| hook | 도입 | – | 자바 입문 열두 번째, 추상 메소드와 추상 클래스 |
| why | 1. 왜 필요할까 | 1 | 상속 편 `Person.hello()`의 몸체("안녕")는 자식이 모두 오버라이딩해서 쓰이지 않음. 또 `new Person("서준")`이 되어 학생도 선생님도 아닌 어중간한 객체가 생김(`서준 안녕` 출력) |
| amethod | 1. 추상 메소드 | 1 | `abstract void hello();` — 몸체 없이 `;`로 끝남. "자식이 꼭 완성하라"는 표시 |
| aclass | 2. 추상 클래스 | 2 | 추상 메소드가 있는데 `class` 앞의 `abstract`를 빼면 컴파일 오류 → `abstract class Person` |
| anew | 2-1. new 불가 | 2 | `new Person("서준")` → 컴파일 오류. 어중간한 객체를 막아 줌 |
| override | 3. 자식이 완성 | 3 | Student·Teacher가 `hello()`를 오버라이딩 → `학생 민수 안녕` / `서준 선생님 안녕` |
| omiss | 3-1. 빠뜨리면? | 3 | Teacher가 `hello()`를 빠뜨리면 컴파일 오류 → 해결은 둘: 오버라이딩하거나, `abstract class Teacher`로 미루기(대신 Teacher도 `new` 불가) |
| members | 4. 추상 클래스의 구성 | 4 | 필드 `name`·생성자·일반 메소드 `bye()`를 가질 수 있음. 자식은 `super(name)`으로 부모 생성자 호출, `s.bye()` → `민수 잘 가` |
| notes | 5. 주의 | 5 | 메모 두 개: 추상 메소드 없는 추상 클래스도 가능 / `abstract final class` → 컴파일 오류(abstract는 "물려받아 완성", final은 "물려받지 마"라 반대) |
| outro | 정리 | – | 6줄 목록, 나레이션에 맞춰 줄 강조, 👍 구독 · 좋아요 |

## User Stories

1. 시청자로서, 첫 화면에서 "자바 입문 열두 번째, 추상 메소드와 추상 클래스"라는 주제를 바로 알고 싶다. 따라오던 시리즈의 다음 편인지 알 수 있기 때문이다.
2. 시청자로서, 상속 편의 `Person`·`Student`·`Teacher`, 민수·서준이 다시 나오길 바란다. 앞에서 배운 코드 위에 새 개념을 쌓을 수 있기 때문이다.
3. 시청자로서, 상속 편 `Person.hello()`의 몸체가 자식들의 오버라이딩 때문에 결국 쓰이지 않는다는 점을 보고 싶다. 몸체 없는 메소드가 왜 필요한지 납득할 수 있기 때문이다.
4. 시청자로서, 지금의 `Person`으로는 `new Person("서준")`이 되어 `서준 안녕`이 출력된다는 것을 보고 싶다. 학생도 선생님도 아닌 어중간한 객체가 생기는 문제를 실감할 수 있기 때문이다.
5. 시청자로서, `abstract void hello();`처럼 몸체 없이 `;`로 끝나는 추상 메소드의 모양을 보고 싶다. 일반 메소드와의 문법 차이를 한눈에 알 수 있기 때문이다.
6. 시청자로서, 추상 메소드가 "자식이 꼭 완성해야 하는 메소드"라는 뜻임을 듣고 싶다. 문법뿐 아니라 의도를 이해할 수 있기 때문이다.
7. 시청자로서, 추상 메소드가 있는데 클래스에 `abstract`를 빼면 컴파일 오류가 나는 것을 보고 싶다. 두 키워드가 함께 다닌다는 규칙을 기억할 수 있기 때문이다.
8. 시청자로서, `abstract class Person`으로 고치면 오류가 사라지는 것을 보고 싶다. 오류의 해결 방법까지 알 수 있기 때문이다.
9. 시청자로서, 추상 클래스로 `new Person("서준")`을 하면 컴파일 오류가 나는 것을 보고 싶다. 추상 클래스는 객체를 만들 수 없다는 것을 확인할 수 있기 때문이다.
10. 시청자로서, 그 오류가 앞에서 본 "어중간한 객체" 문제를 막아 준다는 연결을 듣고 싶다. 규칙을 외우지 않고 이유로 이해할 수 있기 때문이다.
11. 시청자로서, Student와 Teacher가 `hello()`를 오버라이딩해서 각각 `학생 민수 안녕`, `서준 선생님 안녕`이 출력되는 것을 보고 싶다. 추상 메소드가 자식에서 완성되는 모습을 결과로 볼 수 있기 때문이다.
12. 시청자로서, 자식 클래스의 `hello()`에 `@Override`가 붙어 있길 바란다. 상속 편에서 배운 표기와 이어지기 때문이다.
13. 시청자로서, Teacher가 `hello()`를 빠뜨리면 컴파일 오류가 나는 것을 보고 싶다. 추상 메소드가 오버라이딩을 *강제*한다는 것을 확인할 수 있기 때문이다.
14. 시청자로서, 그 오류의 해결 방법이 두 가지(오버라이딩하기, 자식도 `abstract`로 만들기)라는 것을 보고 싶다. 상황에 맞게 고를 수 있기 때문이다.
15. 시청자로서, `abstract class Teacher`로 바꾸면 통과하지만 이제 Teacher도 `new`로 만들 수 없다는 것을 보고 싶다. 미루기의 대가를 정확히 알 수 있기 때문이다.
16. 시청자로서, 추상 클래스도 필드 `name`과 생성자를 가질 수 있다는 것을 보고 싶다. "추상 클래스는 빈 틀"이라는 오해를 풀 수 있기 때문이다.
17. 시청자로서, `new`를 못 하는 추상 클래스의 생성자가 자식의 `super(name)`으로 실행된다는 것을 보고 싶다. 생성자가 왜 필요한지 이해할 수 있기 때문이다.
18. 시청자로서, 추상 클래스의 일반 메소드 `bye()`를 자식 객체 `s`가 물려받아 `민수 잘 가`가 출력되는 것을 보고 싶다. 추상 메소드와 일반 메소드가 한 클래스에 함께 있을 수 있다는 것을 알 수 있기 때문이다.
19. 시청자로서, 추상 메소드가 하나도 없는 추상 클래스도 가능하다는 메모를 보고 싶다. "추상 메소드가 있어야 추상 클래스"라는 잘못된 역규칙을 갖지 않기 때문이다.
20. 시청자로서, `abstract final class`가 컴파일 오류라는 것을 보고 싶다. 지난 편의 final과 이번 편의 abstract가 정반대라는 것을 정리할 수 있기 때문이다.
21. 시청자로서, 그 오류의 이유를 "abstract는 물려받아 완성하라, final은 물려받지 마라"로 듣고 싶다. 두 키워드를 한 번에 기억할 수 있기 때문이다.
22. 시청자로서, 정리 장면에서 항목 전체를 한 화면으로 보고, 나레이션이 말하는 줄이 강조되길 바란다. 복습하기 쉽기 때문이다.
23. 시청자로서, 나레이션과 단어 단위로 맞는 한국어 자막을 보고 싶다. 소리 없이 보거나 빠른 템포에서도 따라갈 수 있기 때문이다.
24. 시청자로서, 나레이션에서 말한 코드·결과·오류가 모두 화면에 보이길 바란다. 말로만 나오는 내용 때문에 혼란스럽지 않기 때문이다.
25. 시청자로서, Person·Student·Teacher가 상속 편과 같은 색으로 구분되길 바란다. 어떤 클래스의 코드인지 바로 알 수 있기 때문이다.
26. 휴대폰 시청자로서, 코드가 한 줄 33자 이하이고 하단 쇼츠 UI에 가리지 않길 바란다. 작은 화면에서도 읽을 수 있기 때문이다.
27. 시청자로서, 영상이 3분을 넘지 않고 지난 영상들과 같은 속도·디자인이길 바란다. 시리즈를 일관되게 볼 수 있기 때문이다.
28. 제작자로서, 화면의 모든 예제가 빌드할 때 실제로 컴파일·실행되고, 대본의 기대 결과와 다르면 빌드가 멈추길 바란다. 틀린 코드가 영상에 나가지 않기 때문이다.
29. 제작자로서, 컴파일 오류 예제도 실제 javac의 오류 문구와 대조되길 바란다. "오류가 난다"는 설명이 사실임을 보장할 수 있기 때문이다.
30. 제작자로서, "추상 메소드 없는 추상 클래스"처럼 *컴파일되어야* 하는 예제도 빌드에서 컴파일을 확인하길 바란다. 메모의 내용도 사실임을 보장할 수 있기 때문이다.
31. 제작자로서, 영상에 나온 예제 프로그램 전체가 파일 하나로 저장되길 바란다. 시청자 질문에 답하거나 나중에 다시 확인할 수 있기 때문이다.
32. 제작자로서, 용어가 GLOSSARY의 표기(추상 메소드·추상 클래스·부모 클래스·자식 클래스·오버라이딩)로 통일되길 바란다. 시리즈 전체의 표기가 흔들리지 않기 때문이다.
33. 제작자로서, 렌더링 결과가 1080×1920이고 오디오 트랙이 있는지 확인되길 바란다. 업로드 전에 규격 문제를 잡을 수 있기 때문이다.
34. 제작자로서, README의 영상 목록에 이 영상의 행이 추가되길 바란다. 시리즈 기록이 이어지기 때문이다.

## Implementation Decisions

- **새 영상 프로젝트**: `java-abstract-shorts`. 직전 영상(static과 final)의 음성 생성 스크립트와 빌드 스크립트를 복사해 만든다(템포 1.2배, TTS `+34%`). 직전 영상에는 출력 대조·컴파일 오류 대조·컴파일 성공 확인 헬퍼가 모두 있으므로 그대로 쓴다. 디자인 토큰·글꼴·화면 구성·모션은 바꾸지 않는다.
- **상단 바 브랜드**: "자바 입문 abstract 정리"로 하고, "abstract"는 주황으로 강조한다. 진행 표시는 5칸이며, 2-1은 2번째 칸, 3-1은 3번째 칸에 속한다.
- **예시 데이터** (영상 전체에서 하나로 통일, 색은 상속 편과 같게)
  - `Person` (k1): 추상 클래스. 필드 `String name`, 생성자 `Person(String name)`, 추상 메소드 `abstract void hello();`, 일반 메소드 `bye()`(`name + " 잘 가"` 출력).
  - `Student` (k2): `extends Person`, 필드 `int score`, 생성자에서 `super(name)`, `@Override hello()` → `"학생 " + name + " 안녕"`. 객체는 민수·85.
  - `Teacher` (k3): `extends Person`, 생성자에서 `super(name)`, `@Override hello()` → `name + " 선생님 안녕"`. 객체는 서준. 상속 편의 `subject` 필드는 이번 편에서 쓰지 않는다(코드 길이 절약).
  - why 장면만 상속 편 그대로의 일반 클래스 `Person`(몸체 있는 `hello()` → `name + " 안녕"`)을 쓴다.
  - 생성자·`bye()`는 members 장면에서 처음 화면에 보여 준다. 그 전 장면에서는 숨김 줄로 완전한 프로그램을 만든다.
- **장면별 기대 결과**
  - why: `서준 안녕`
  - override: `학생 민수 안녕`, `서준 선생님 안녕` 두 줄
  - omiss: `abstract class Teacher`로 바꾼 코드는 컴파일 성공, 그 Teacher를 `new` 하면 컴파일 오류
  - members: `민수 잘 가`
  - notes: 추상 메소드 없는 추상 클래스는 컴파일 성공
  - 컴파일 오류 예제와 javac 오류 문구(대조 기준, 기획 단계에서 로컬 javac로 확인함):
    - aclass: `Person is not abstract and does not override abstract method hello() in Person`
    - anew: `Person is abstract; cannot be instantiated`
    - omiss(빠뜨림): `Teacher is not abstract and does not override abstract method hello() in Person`
    - omiss(abstract Teacher를 new): `Teacher is abstract; cannot be instantiated`
    - notes: `illegal combination of modifiers: abstract and final`
- **장면 구성 요소**
  - why는 상속 편 `Person` 코드(몸체 줄에 `mark`)와 `new Person("서준")` 실행 결과로 두 가지 아쉬운 점을 보여 준다.
  - amethod는 일반 메소드와 추상 메소드를 두 개념 비교 카드(`.vs`)로 대비한다(`{ … }` vs `;`).
  - omiss는 오류 예제 아래에 해결 방법 두 가지를 번호 목록 또는 비교 카드로 보여 준다.
  - notes는 메모(`.note`) 하나와 경고(`.warn`) 하나로 구성한다.
- **예제 표시 헬퍼**: 출력이 있는 예제는 출력 대조 헬퍼로, 컴파일 오류 예제는 오류 대조 헬퍼로, 컴파일만 확인할 예제는 컴파일 성공 헬퍼로 넣는다. 예제 프로그램 전체는 빌드가 예제 목록 파일로 저장한다.
- **대본**
  - 장면 id는 위 표와 같다.

- **정리 장면 6줄**
  1. 추상 메소드 → 몸체 없이 `;`로 선언만
  2. 추상 메소드가 있으면 클래스도 `abstract`
  3. 추상 클래스는 `new` 불가
  4. 자식은 추상 메소드를 꼭 오버라이딩
  5. 아니면 자식도 `abstract`로 미루기
  6. 필드·생성자·일반 메소드도 가질 수 있음

## Testing Decisions

- **좋은 테스트의 기준**: 시청자가 화면에서 보는 결과를 검사한다. 즉 예제의 실제 출력, 실제 컴파일 오류, 실제 컴파일 성공이 대본의 기대값과 같은지 본다. 빌드 스크립트 내부 구조나 HTML 마크업은 검사하지 않는다.
- **테스트 지점은 하나**: 기존 빌드 과정의 Java 예제 검증을 그대로 쓴다. 빌드는 장면마다 예제를 실제 JDK로 컴파일·실행하고, 기대와 다르면 멈춘다. 새 테스트 지점은 만들지 않는다.
- **대조 항목**
  - 출력 대조(3건): why `서준 안녕`, override 두 줄, members `민수 잘 가`
  - 컴파일 오류 대조(5건): `abstract` 없는 클래스, 추상 클래스 `new`, 추상 메소드 빠뜨림, abstract Teacher `new`, `abstract final`
  - 컴파일 성공 확인(2건): abstract Teacher, 추상 메소드 없는 추상 클래스
- **빌드 이후 검증** (기존 절차)
  - HyperFrames check: 오류 0건, 레이아웃 겹침·넘침 없음. `line_unread` 경고는 허용한다.
  - snapshot: 모든 장면을 확인하고, 가장 빽빽한 장면(omiss 또는 members)을 390px 폭으로 줄여 모바일 가독성을 확인한다.
  - 자막: 대사 중 자막 없는 시간이 0초인지 확인한다.
  - 렌더링 후 ffprobe: 1080×1920, 오디오 트랙 존재.
- **수동 검토**: 나레이션 문장이 화면의 기대 결과와 같은지 직접 확인한다(예: "학생 민수 안녕, 서준 선생님 안녕이 나와요"). 자동 대조는 예제 결과까지만 하기 때문이다.
- **참고할 기존 사례**: static과 final 편의 컴파일 오류 장면(final 메소드·클래스, "main도 static" 메모)과 상속 편의 오버라이딩·`super()` 장면.

## Out of Scope

- 부모 타입 변수에 자식 객체 담기(`Person p = new Student(...)`), 다형성, 업캐스팅 — 다음 편 예고도 하지 않는다
- 인터페이스와 추상 클래스 비교
- `abstract`와 `static`·`private`를 함께 쓸 수 없는 규칙
- 추상 메소드에 몸체를 쓰면 나는 오류(`abstract methods cannot have a body`)
- 일반 메소드 안에서 추상 메소드를 부르는 방식(템플릿 메소드 패턴)
- 접근 제어자(`protected` 등)
- 디자인·템포·제작 도구의 변경
