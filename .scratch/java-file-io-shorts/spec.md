# 스펙: 자바 입문 스물한 번째 — 텍스트 파일 읽기·쓰기

Status: ready-for-agent

## Problem Statement

시청자는 지금까지 리스트에 점수를 담고, 스트림으로 합계를 구했다. 하지만 프로그램이 끝나면 그 데이터는 모두 사라진다. 다음에 실행할 때도 쓰려면 파일에 저장하고 다시 읽어야 한다. 20편에서 예외와 체크 예외를 배웠으므로, 이제 `IOException` 처리가 필수인 파일 입출력을 배울 준비가 됐다.

입문자가 텍스트 파일 읽기·쓰기를 처음 배울 때 특히 막히는 점은 다음과 같다.

- `FileWriter`, `BufferedWriter`, `FileReader`, `BufferedReader`처럼 클래스가 여러 개 겹쳐 나와서 각각의 역할을 모름
- 파일을 닫지 않으면 내용이 저장되지 않을 수 있다는 것, 그리고 자동으로 닫는 법(try-with-resources)
- 줄바꿈을 직접 넣어야 한다는 것(`newLine()`)
- `readLine()`으로 끝까지 읽는 반복문의 모양(`null`이면 끝)
- 다시 실행하면 기존 내용이 사라지는 덮어쓰기와, 뒤에 덧붙이는 이어쓰기의 차이
- 파일에서 읽은 값은 문자열이라 계산하려면 변환해야 한다는 것
- 파일 코드에 왜 항상 `try-catch`나 `throws`가 붙는지
- 파일이 어느 폴더에 생기는지

3분 이하 세로 쇼츠 한 편으로, `scores.txt` 파일 하나를 실제로 쓰고 읽은 결과로 이 내용을 정확히 보여 줄 영상이 필요하다.

## Solution

시리즈 스물한 번째 영상 "텍스트 파일 읽기·쓰기"를 기존 영상과 같은 디자인·제작 방식으로 만든다.

- 영상 규격: 1080×1920, 약 2분 30초, 1.2배 템포
- 흐름: 프로그램이 끝나도 남는 데이터에서 출발해, 쓰고 → 이어 쓰고 → 읽고 → 읽은 값으로 계산하고 → 파일 예외를 처리하고 → 짧게 쓰는 법으로 마무리
- 파일은 `scores.txt` 하나. 한 줄에 `이름,점수` 형식이고, 최종 내용은 `민수,85` / `서준,92` / `지우,78` 세 줄. 합계 255는 19편 스트림 합계와 같다
- 장면마다 화면에 "scores.txt" 파일 내용 상자를 두어, 코드 실행 뒤 파일이 어떻게 바뀌었는지 보여 준다

장면 구성은 아래와 같다. 진행 표시가 5칸이라 기획 때의 STEP 6개를 5칸에 맞췄다. 이어쓰기를 쓰기 STEP의 하위 장면(1-1)으로 옮겼고, 그래서 처음 쓰기는 두 줄(민수·서준), 이어쓰기로 지우를 덧붙여 세 줄이 된다.

| id | 장면 | 진행 표시 | 내용 |
|---|---|---|---|
| hook | 도입 | — | `.hook` + 150px "파일" 제목. 리스트 데이터는 프로그램이 끝나면 사라지고, 파일은 남는다 |
| write | 1. 쓰기 | 1 | try-with-resources로 `BufferedWriter`(`FileWriter("scores.txt")`) 열기 → `write("민수,85")` + `newLine()` → 서준까지 두 줄. 블록이 끝나면 자동으로 닫힘. `.note`: 이름만 쓰면 프로그램을 실행한 폴더에 생김 |
| append | 1-1. 이어쓰기 | 1 | `new FileWriter("scores.txt", true)`로 지우를 덧붙여 세 줄. 함정: `true`를 빼면 덮어써서 `지우,78` 한 줄만 남음 |
| read | 2. 읽기 | 2 | `BufferedReader`의 `readLine()`을 `null`이 나올 때까지 `while`로 반복해 세 줄 출력 |
| sum | 3. 읽어서 계산 | 3 | `split(",")`으로 이름과 점수를 나누고 `Integer.parseInt`로 바꿔 합계 255 |
| except | 4. 파일 예외 | 4 | 이름을 잘못 쓴 `score.txt`를 읽으면 `FileNotFoundException`. `IOException`은 체크 예외(20편)라 `catch`나 `throws`가 필수 |
| files | 5. 짧게 쓰기 | 5 | `Files.writeString`, `Files.readAllLines(Path.of("scores.txt"))`로 같은 일을 짧게. `main`에 `throws IOException` |
| outro | 정리 | — | 목록 전체 → 나레이션에 맞춰 줄 강조. `.note`로 한글은 UTF-8. 👍 구독 · 좋아요 |

## User Stories

1. 시청자로서, 첫 화면에서 "자바 입문 스물한 번째, 텍스트 파일 읽기·쓰기"라는 주제를 바로 알고 싶다. 시리즈의 다음 편인지 알 수 있기 때문이다.
2. 시청자로서, 리스트에 담은 데이터는 프로그램이 끝나면 사라진다는 것을 듣고 싶다. 파일이 왜 필요한지 알 수 있기 때문이다.
3. 시청자로서, 영상 전체에서 `scores.txt` 파일 하나만 쓰고 읽는 것을 보고 싶다. 파일이 장면마다 어떻게 바뀌는지 따라가기 쉽기 때문이다.
4. 시청자로서, 코드 옆이나 아래에 "scores.txt" 파일 내용 상자가 보이길 원한다. 코드를 실행한 결과 파일에 무엇이 들어갔는지 눈으로 확인할 수 있기 때문이다.
5. 시청자로서, `FileWriter`는 파일을 열고 `BufferedWriter`는 그것을 감싸 편하게 쓰게 해 준다는 역할 구분을 듣고 싶다. 클래스가 겹쳐 나오는 이유를 알 수 있기 때문이다.
6. 시청자로서, `write`로 글자를 쓰고 `newLine()`으로 줄을 바꾼다는 것을 보고 싶다. 줄바꿈을 직접 넣어야 한다는 것을 알 수 있기 때문이다.
7. 시청자로서, 쓰기 코드를 실행한 뒤 파일에 `민수,85`와 `서준,92` 두 줄이 생긴 것을 보고 싶다. 쓰기가 실제로 동작하는 것을 확인할 수 있기 때문이다.
8. 시청자로서, 파일은 다 쓰면 닫아야 하고, `try` 괄호 안에서 열면 블록이 끝날 때 자동으로 닫힌다는 것을 보고 싶다. 닫기를 잊는 실수를 피할 수 있기 때문이다.
9. 시청자로서, 이 문법의 이름이 try-with-resources라는 것을 듣고 싶다. 다른 자료에서 같은 이름을 만나도 알아볼 수 있기 때문이다.
10. 시청자로서, 파일 이름만 쓰면 프로그램을 실행한 폴더에 생긴다는 메모를 보고 싶다. 파일을 찾아 헤매지 않게 되기 때문이다.
11. 시청자로서, `new FileWriter("scores.txt", true)`처럼 `true`를 넣으면 기존 내용 뒤에 덧붙는다는 것을 보고 싶다. 이어쓰기 방법을 알 수 있기 때문이다.
12. 시청자로서, 이어쓰기 뒤 파일이 세 줄이 된 것을 보고 싶다. 기존 내용이 남아 있다는 것을 확인할 수 있기 때문이다.
13. 시청자로서, `true`를 빼면 덮어써서 `지우,78` 한 줄만 남는 함정을 보고 싶다. 데이터를 날리는 실수를 피할 수 있기 때문이다.
14. 시청자로서, 덮어쓰기가 기본이고 이어쓰기는 직접 정해야 한다는 것을 듣고 싶다. 기본 동작을 정확히 알 수 있기 때문이다.
15. 시청자로서, `BufferedReader`의 `readLine()`이 한 줄씩 읽어 준다는 것을 보고 싶다. 파일을 읽는 기본 방법을 알 수 있기 때문이다.
16. 시청자로서, 더 읽을 줄이 없으면 `readLine()`이 `null`을 돌려준다는 것을 보고 싶다. 반복을 언제 멈추는지 알 수 있기 때문이다.
17. 시청자로서, `while ((line = r.readLine()) != null)` 반복문으로 세 줄을 모두 출력하는 결과를 보고 싶다. 끝까지 읽는 관용구를 익힐 수 있기 때문이다.
18. 시청자로서, 읽은 한 줄은 문자열이라 `split(",")`으로 이름과 점수를 나눈다는 것을 보고 싶다. 파일 형식을 다루는 법을 알 수 있기 때문이다.
19. 시청자로서, 점수 문자열을 `Integer.parseInt`로 바꿔 더하면 합계 255가 나오는 것을 보고 싶다. 파일의 데이터로 계산하는 법을 알 수 있기 때문이다.
20. 시청자로서, 합계 255가 19편 스트림에서 구한 합계와 같다는 연결을 듣고 싶다. 시리즈의 흐름이 이어지기 때문이다.
21. 시청자로서, 파일 이름을 잘못 쓰면 `FileNotFoundException`이 나는 것을 실제 메시지로 보고 싶다. 실제로 자주 하는 실수를 미리 알 수 있기 때문이다.
22. 시청자로서, `IOException`은 체크 예외라서 처리하지 않으면 컴파일조차 안 된다는 것을 20편과 연결해 듣고 싶다. 파일 코드에 왜 항상 `try-catch`가 붙는지 이해할 수 있기 때문이다.
23. 시청자로서, `catch (IOException e)`로 잡아 안내 문구를 출력하는 모습을 보고 싶다. 파일 예외를 처리하는 법을 알 수 있기 때문이다.
24. 시청자로서, `Files.writeString`과 `Files.readAllLines`로 같은 일을 짧게 쓰는 법을 보고 싶다. 요즘 코드에서 자주 보는 방식에 익숙해지기 때문이다.
25. 시청자로서, `readAllLines`가 모든 줄을 리스트로 돌려준다는 것을 보고 싶다. 17편에서 배운 리스트와 연결되기 때문이다.
26. 시청자로서, 짧은 방식도 `IOException` 처리가 필요해 `main`에 `throws IOException`을 붙인다는 것을 보고 싶다. 20편의 `throws`를 실제로 쓰는 모습을 볼 수 있기 때문이다.
27. 시청자로서, 한글이 깨질 때는 UTF-8을 확인하라는 메모를 한 줄 보고 싶다. 자주 만나는 문제를 미리 알 수 있기 때문이다.
28. 시청자로서, 정리 장면에서 쓰기·이어쓰기·읽기·예외·짧게 쓰기를 한 화면에 보고, 나레이션에 맞춰 강조되는 줄을 따라가고 싶다. 복습하기 쉽기 때문이다.
29. 시청자로서, 모든 대사가 단어 단위로 맞춰진 한국어 자막으로 나오길 원한다. 소리 없이 봐도 이해할 수 있기 때문이다.
30. 시청자로서, 모바일 화면에서 코드와 파일 내용 상자가 읽히는 크기이길 원한다. 쇼츠는 휴대폰으로 보기 때문이다.
31. 시청자로서, 화면에 나온 코드를 그대로 따라 쳐도 같은 파일과 출력이 나오길 원한다. 영상을 믿고 따라 할 수 있기 때문이다.
32. 제작자로서, 화면의 모든 예제가 빌드 중에 실제로 컴파일·실행되고, 출력뿐 아니라 실행 뒤 `scores.txt` 내용까지 대본의 기대값과 대조되길 원한다. 파일 내용 상자가 실제와 달라지지 않기 위해서다.
33. 제작자로서, 예제가 빌드를 실행한 폴더가 아니라 예제마다 만든 임시 폴더에서 실행되길 원한다. 저장소에 `scores.txt`가 생기거나 예제끼리 파일을 섞어 쓰지 않기 위해서다.
34. 제작자로서, 앞 장면의 파일 상태가 필요한 장면(이어쓰기, 읽기, 계산)은 앞 장면의 코드를 같은 프로그램에서 먼저 실행해 같은 상태를 만들길 원한다. 장면마다 파일 내용이 대본과 일치하게 하기 위해서다.
35. 제작자로서, 영상에 나온 예제 프로그램 전체가 예제 기록 파일로 남길 원한다. 시청자 질문에 같은 코드로 답할 수 있기 때문이다.
36. 제작자로서, 디자인·템포·자막 방식이 20편과 같길 원한다. 시리즈의 일관성을 지키기 위해서다.
37. 제작자로서, 업로드 후 README 영상 목록에 행을 추가하고 싶다. 시리즈 기록을 유지하기 위해서다.

## Implementation Decisions

- **새 영상 프로젝트**: `java-file-io-shorts`. 20편(예외)의 음성 생성 스크립트와 빌드 스크립트를 복사해 만든다(`SPEED = 1.2`, TTS `+34%`). 디자인 토큰·글꼴·화면 구성·모션은 바꾸지 않는다. 20편이 먼저 완성되어야 한다.
- **상단 바 브랜드**: "자바 입문 <em>파일</em> 읽기·쓰기 정리" 형태. 진행 표시는 5칸이며 1-1은 1번째 칸에 속한다.
- **용어** (GLOSSARY, 기획 단계에서 등록함): try-with-resources, 덮어쓰기 / 이어쓰기. 20편 용어 예외·체크 예외·throws·try-catch, 기존 용어 리스트·import를 그대로 쓴다.
  - "append 모드"(단독), "자동 close 문법"은 쓰지 않는다
  - 19편 용어집의 결정대로, 파일 입출력의 "스트림"이라는 말은 쓰지 않는다
- **읽는 법**: 트라이 위드 리소스, 버퍼드 라이터, 버퍼드 리더, 파일 라이터, 리드 라인, 뉴 라인, 파일즈 등. 클래스 이름은 대본에서 한글 발음으로 쓴다.
- **예시 데이터**: 파일 이름 `scores.txt`, 형식 `이름,점수`(쉼표 뒤 공백 없음), 줄 순서 민수(k1) → 서준(k2) → 지우(k3). 파일 내용 상자의 줄 색도 사람을 따라간다. 잘못된 파일 이름은 `score.txt`(s 빠짐).
- **장면별 기대 결과** (대조 기준)
  - 파일 내용: write — `민수,85` `서준,92` / append — 세 줄 / append 함정 — `지우,78` 한 줄
  - 출력: read — 세 줄 그대로 / sum — `255` / files — 읽은 리스트 `[민수,85, 서준,92, 지우,78]`
  - except: `FileNotFoundException`의 메시지 `score.txt (No such file or directory)`. 실행 환경에 따라 문구가 다를 수 있으므로 빌드가 얻은 실제 문구로 그린다
- **컴파일·실행 헬퍼 확장** (20편 빌드 기준)
  - 예제 프로그램을 예제마다 만든 임시 폴더 안에서 실행한다(지금은 빌드를 실행한 폴더에서 실행됨)
  - 실행이 끝난 뒤 임시 폴더의 `scores.txt` 내용을 읽어, 기대 내용이 주어지면 대조하고 다르면 빌드를 멈춘다
  - 화면의 "scores.txt" 파일 내용 상자는 그 실제 내용으로 그린다(출력 상자와 같은 방식, 라벨만 파일 이름)
  - 앞 장면의 파일 상태가 필요한 장면은 앞 장면 코드를 보이지 않는 사전 코드로 먼저 실행한다
  - 자바 파일 입출력 클래스(`java.io.*`, `java.nio.file.*`) import를 기본 import에 더한다. 화면에 import 줄을 보여 줄지는 장면마다 정한다
- **33자 제한**: `new BufferedWriter(new FileWriter(...))`처럼 긴 줄은 `new FileWriter` 앞에서 줄을 바꾼다. try-with-resources 괄호도 의미 단위로 나눈다.
- **사실 표현 주의**
  - "닫지 않으면 내용이 저장되지 않을 수 있다"처럼 완화해서 말한다(항상 사라진다고 단정하지 않음)
  - `FileReader`/`FileWriter`는 자바 18부터 기본 인코딩이 UTF-8이다. 인코딩은 정리 장면 메모 한 줄로만 다루고 자세한 버전 설명은 하지 않는다
  - `FileNotFoundException`은 `IOException`의 자식 클래스라 `catch (IOException e)`로 잡힌다는 것을 정확히 말한다

## Testing Decisions

- **좋은 테스트의 기준**: 시청자가 화면에서 보는 결과를 검사한다. 즉 실제로 컴파일·실행한 예제의 출력, 예외 문구, 그리고 실행 뒤 `scores.txt`의 내용이 대본의 기대값과 같은지 본다. 빌드 스크립트 내부 구조나 HTML 마크업은 검사하지 않는다.
- **테스트 지점은 하나**: 빌드 자체. 20편 빌드의 대조 헬퍼를 쓰고, 임시 폴더 실행과 파일 내용 대조는 기존 헬퍼의 확장으로 넣는다. 새 테스트 지점은 만들지 않는다.
- **대조 항목**
  - 파일 내용 대조: write, append, append 함정, files(쓰기 쪽)
  - 출력 대조: read, sum, except(처리 문구), files(읽기 쪽)
  - 기대와 다르면(출력이나 파일 내용이 다르거나, 컴파일 오류가 나면) 빌드를 멈춘다
  - 빌드가 끝난 뒤 저장소에 `scores.txt`가 생기지 않았는지 확인한다
- **빌드 이후 검증** (기존 절차)
  - HyperFrames check: 오류 0건, 레이아웃 겹침·넘침 없음. `line_unread` 경고는 허용한다
  - snapshot: 모든 장면을 확인하고, 가장 빽빽한 장면(read 또는 sum)을 390px 폭으로 줄여 모바일 가독성을 확인한다
  - 자막: 대사 중 자막 없는 시간이 0초인지 확인한다
  - 렌더링 후 ffprobe: 1080×1920, 오디오 트랙 존재
- **수동 검토**: 나레이션 문장이 화면의 기대 결과와 같은지 직접 확인한다(예: "두 줄이 생겼어요", "지우만 남아요", "이백오십오"). 자동 대조는 예제 결과까지만 하기 때문이다.
- **참고할 기존 사례**: 20편 빌드의 출력·예외 대조 헬퍼와 정리 장면, 19편 count 장면(합계 255), 17편 리스트 출력.

## Out of Scope

- 바이트 스트림(`FileInputStream`/`FileOutputStream`), 이진 파일
- `Scanner`로 파일 읽기, `PrintWriter`
- 인코딩 지정 생성자, 자바 버전별 기본 인코딩의 자세한 설명
- 절대 경로·폴더 만들기·파일 삭제·존재 확인(`File`, `Files.exists` 등)
- CSV의 따옴표·공백 처리 등 형식의 예외 상황
- `Files.lines`와 스트림의 결합
- `flush()`의 자세한 설명
- 디자인·템포·제작 도구의 변경

## Further Notes

- 시리즈 순서: … → 스트림(19) → 예외(20) → 텍스트 파일 읽기·쓰기(21).
- 기획 때 STEP 6개(쓰기, 읽기, 이어쓰기, 읽어서 계산, 파일 예외, 짧게 쓰기)로 합의했으나, 진행 표시가 5칸이라 이어쓰기를 쓰기 STEP의 하위 장면(1-1)으로 옮겼다. 그에 맞춰 처음 쓰기는 두 줄, 이어쓰기로 세 번째 줄을 덧붙인다(최종 세 줄과 합계 255는 합의한 그대로).
- 예외 문구는 운영체제에 따라 다르므로 화면에는 빌드가 얻은 실제 문구를 그리고, 기획 중 확인한 문구는 로컬 macOS · OpenJDK 25.0.4(영문 로케일) 기준이다.
- 유튜브 제목 형식: "자바 입문 21편: 텍스트 파일 읽기·쓰기 | BufferedWriter · BufferedReader · try-with-resources · Files" (꺾쇠 금지).
- 커밋·푸시는 사용자가 요청할 때만 한다.
