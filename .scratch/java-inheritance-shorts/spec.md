# 스펙: 자바 입문 열 번째 — 클래스의 상속

Status: ready-for-agent

## Problem Statement

자바 입문 시리즈를 따라온 시청자는 지난 두 영상에서 클래스·객체·필드와 메소드·생성자·`this`·기본 생성자·오버로딩을 배웠다. 하지만 비슷한 클래스를 여러 개 만들 때 같은 필드와 메소드를 반복해서 적어야 하는 문제를 어떻게 푸는지는 아직 모른다. 부모 클래스와 자식 클래스, `extends`, 오버라이딩, `super`는 입문자가 자주 헷갈리는 개념이다. 특히 오버라이딩과 오버로딩의 차이와, 부모 생성자가 언제 어떻게 실행되는지를 헷갈린다. 3분 이하 세로 쇼츠 한 편으로 이 개념들을 정확하게, 실제로 실행되는 예제로 보여 줄 영상이 필요하다.

## Solution

시리즈 열 번째 영상 "클래스의 상속"을 기존 영상과 같은 디자인·제작 방식으로 만든다.

- 영상 규격: 1080×1920, 약 2분 30초, 1.2배 템포
- 예시 클래스: 지난 영상의 `Student`를 이어서 쓴다. 중복된 `name`·`hello()`를 부모 클래스 `Person`으로 빼내는 장면에서 상속의 필요성을 보여 준다.
- 두 번째 자식 클래스: `Teacher`를 함께 두어, 자식마다 다른 필드와 오버라이딩 결과를 비교한다.

장면 구성은 아래와 같다.

| 장면 | 진행 표시 | 내용 |
|---|---|---|
| 도입 | – | 자바 입문 열 번째, 클래스의 상속 |
| 1. `extends` | 1 | Student·Teacher의 중복 코드 → 부모 클래스 Person으로 빼기, 비유 한 문장 |
| 2. 물려받은 것 쓰기 | 2 | 자식 객체로 부모의 필드·메소드 호출("민수 안녕"), 자식만의 필드 `score`·`subject` |
| 3. 오버라이딩 | 3 | 같은 `hello()`가 객체마다 다른 결과, `@Override` 한 문장, 오버로딩과 비교 카드 |
| 4. `super()` | 4 | 자식 생성자가 부모 생성자를 먼저 호출, 실행 순서를 출력으로 확인 |
| 4-1. 주의 | 4 | `super(...)`가 없을 때 부모에 기본 생성자가 없으면 컴파일 오류 |
| 5. `super.메소드()` | 5 | 오버라이딩한 메소드 안에서 부모 버전 호출 |
| 5-1. 주의 | 5 | `extends`에는 클래스 하나만, 부모 클래스는 하나만 |
| 정리 | – | 항목 목록, 나레이션에 맞춰 줄 강조, 👍 구독 · 좋아요 |

## User Stories

1. 시청자로서, 영상 첫 화면에서 "자바 입문 열 번째, 클래스의 상속"이라는 주제를 바로 알고 싶다. 내가 따라오던 시리즈의 다음 편인지 알 수 있기 때문이다.
2. 시청자로서, 지난 영상의 `Student`·민수·85가 다시 나오길 바란다. 앞에서 배운 내용 위에 새 개념을 쌓을 수 있기 때문이다.
3. 시청자로서, Student와 Teacher에 같은 `name`·`hello()`가 반복된 코드를 먼저 보고 싶다. 상속이 왜 필요한지 납득할 수 있기 때문이다.
4. 시청자로서, 중복 부분을 Person으로 빼고 `extends Person`을 붙이는 장면을 보고 싶다. `extends`의 문법과 의미를 함께 익힐 수 있기 때문이다.
5. 시청자로서, "부모가 자식에게 물려준다"는 비유를 한 문장으로 듣고 싶다. 개념을 직관적으로 기억할 수 있기 때문이다.
6. 시청자로서, Student 클래스 안에 `hello()`가 없는데도 `s1.hello()`가 "민수 안녕"을 출력하는 것을 보고 싶다. 물려받은 메소드가 실제로 동작한다는 것을 확인할 수 있기 때문이다.
7. 시청자로서, 자식 객체에서 부모의 필드 `name`도 점을 찍어 쓸 수 있다는 것을 보고 싶다. 필드도 물려받는다는 것을 알 수 있기 때문이다.
8. 시청자로서, Student에는 `score`, Teacher에는 `subject`처럼 자식마다 자기 필드를 더할 수 있다는 것을 보고 싶다. 상속이 "복사"가 아니라 "확장"이라는 것을 이해할 수 있기 때문이다.
9. 시청자로서, Person·Student·Teacher가 모든 화면에서 항상 같은 색으로 구분되길 바란다. 어느 코드가 어느 클래스인지 헷갈리지 않기 때문이다.
10. 시청자로서, 같은 `hello()`를 불러도 Student는 "학생 민수 안녕", Teacher는 "서준 선생님 안녕"을 출력하는 것을 보고 싶다. 오버라이딩의 효과를 결과로 확인할 수 있기 때문이다.
11. 시청자로서, 오버라이딩이 "물려받은 메소드를 같은 이름·같은 매개변수로 다시 정의하는 것"이라는 정확한 정의를 듣고 싶다. 용어를 바르게 쓸 수 있기 때문이다.
12. 시청자로서, `@Override`가 컴파일러에게 진짜 오버라이딩인지 확인을 맡기는 표시라는 설명을 한 문장으로 듣고 싶다. 코드에 왜 붙이는지 알 수 있기 때문이다.
13. 시청자로서, 오버로딩과 오버라이딩을 나란히 비교한 카드를 보고 싶다. 지난 영상에서 배운 오버로딩과 헷갈리지 않기 때문이다.
14. 시청자로서, 자식 생성자 안에서 `super(name)`으로 부모 생성자를 호출하는 코드를 보고 싶다. 부모의 필드를 생성자로 채우는 방법을 알 수 있기 때문이다.
15. 시청자로서, 생성자마다 출력문을 넣은 실행 결과로 "부모 생성자가 먼저, 자식 생성자가 다음"이라는 순서를 확인하고 싶다. 말로만 듣는 것보다 확실히 기억할 수 있기 때문이다.
16. 시청자로서, `super(name);`을 지우면 컴파일 오류가 나는 것을 보고 싶다. 실제로 코드를 짤 때 만날 오류를 미리 알 수 있기 때문이다.
17. 시청자로서, 그 오류의 이유를 지난 영상의 "생성자를 직접 만들면 기본 생성자가 생기지 않는다"와 연결해서 듣고 싶다. 앞뒤 개념이 하나로 이어지기 때문이다.
18. 시청자로서, 오버라이딩한 `hello()` 안에서 `super.hello()`로 부모 버전을 부르고 점수를 덧붙여 "민수 안녕 / 점수 85"가 나오는 것을 보고 싶다. 부모 동작을 버리지 않고 확장하는 방법을 알 수 있기 때문이다.
19. 시청자로서, `super()`(생성자 호출)와 `super.메소드()`(메소드 호출)가 다르다는 것을 구분해서 보고 싶다. 같은 키워드의 두 가지 쓰임을 헷갈리지 않기 때문이다.
20. 시청자로서, `extends Person, Teacher`처럼 부모를 둘 적으면 컴파일 오류가 나는 것을 보고 싶다. "부모 클래스는 하나만"이라는 규칙을 확실히 알 수 있기 때문이다.
21. 시청자로서, 정리 장면에서 배운 항목 전체를 한 화면으로 보고, 나레이션이 말하는 항목이 강조되길 바란다. 복습하기 쉽기 때문이다.
22. 시청자로서, 나레이션과 단어 단위로 맞는 한국어 자막을 보고 싶다. 소리 없이 보거나 빠른 템포에서도 따라갈 수 있기 때문이다.
23. 시청자로서, 나레이션에서 말한 코드·결과·오류가 모두 화면에 보이길 바란다. 말로만 나오는 내용 때문에 혼란스럽지 않기 때문이다.
24. 휴대폰 시청자로서, 코드가 한 줄 33자 이하이고 하단 쇼츠 UI에 가리지 않길 바란다. 작은 화면에서도 읽을 수 있기 때문이다.
25. 시청자로서, 영상이 3분을 넘지 않고 지난 영상들과 같은 속도·디자인이길 바란다. 시리즈를 일관되게 볼 수 있기 때문이다.
26. 제작자로서, 화면의 모든 예제가 빌드할 때 실제로 컴파일·실행되고 대본의 기대 결과와 다르면 빌드가 멈추길 바란다. 틀린 코드가 영상에 나가지 않기 때문이다.
27. 제작자로서, 컴파일 오류 예제도 실제 컴파일러의 오류와 대조되길 바란다. "오류가 난다"는 설명이 사실임을 보장할 수 있기 때문이다.
28. 제작자로서, 영상에 나온 예제 프로그램 전체가 파일 하나로 저장되길 바란다. 시청자 질문에 답하거나 나중에 다시 확인할 수 있기 때문이다.
29. 제작자로서, 용어가 GLOSSARY의 표기(부모 클래스·자식 클래스·오버라이딩)로 통일되길 바란다. 시리즈 전체의 표기가 흔들리지 않기 때문이다.
30. 제작자로서, 렌더링 결과가 1080×1920이고 오디오 트랙이 있는지 자동으로 확인되길 바란다. 업로드 전에 규격 문제를 잡을 수 있기 때문이다.
31. 제작자로서, README의 영상 목록에 이 영상의 행이 추가되길 바란다. 시리즈 기록이 이어지기 때문이다.

## Implementation Decisions

- **새 영상 프로젝트**: `java-inheritance-shorts`. 직전 영상(메소드와 생성자)의 음성 생성 스크립트와 빌드 스크립트를 복사해 만든다(템포 1.2배). 디자인 토큰·글꼴·화면 구성·모션은 바꾸지 않는다.
- **상단 바 브랜드**: "자바 상속 정리", 키워드 "상속"은 주황으로 강조한다. 진행 표시는 5칸이고, 4-1은 4칸, 5-1은 5칸에 속한다.
- **예시 데이터** (영상 전체에서 하나로 통일)
  - `Person`: 부모 클래스, 필드 `name`, 메소드 `hello()`는 `name + " 안녕"`을 출력한다. 색 k1.
  - `Student extends Person`: 필드 `score`, 값 민수·85. 색 k2.
  - `Teacher extends Person`: 필드 `subject`, 값 서준·수학. 색 k3.
- **장면별 사용 범위**: Teacher는 STEP 1~3에만 나온다. STEP 4·5는 Person과 Student만 사용한다.
- **생성자를 쓰는 시점**: STEP 1~3은 생성자 없이 필드에 직접 대입한다. STEP 4부터 `Person(String name)`과, `super(name)`을 호출한 뒤 `this.score`를 채우는 `Student(String name, int score)`를 쓴다. STEP 4의 실행 순서 예제는 각 생성자에 출력문을 한 줄씩 둔다.
- **장면별 기대 결과**
  - STEP 2: "민수 안녕"
  - STEP 3: "학생 민수 안녕", "서준 선생님 안녕"
  - STEP 4: 부모 생성자의 출력 → 자식 생성자의 출력 순서
  - STEP 5: "민수 안녕", "점수 85" 두 줄
  - 4-1·5-1: 컴파일 오류
- **오버로딩과 비교**: STEP 3에 두 개념 비교 카드를 둔다. 오버로딩은 같은 클래스에서 이름은 같고 매개변수가 다르다. 오버라이딩은 자식 클래스에서 이름·매개변수가 같고 내용만 다시 정의한다.
- **예제 표시 헬퍼**: 출력이 있는 예제는 출력 대조 헬퍼로, 컴파일 오류 예제는 오류 대조 헬퍼로 넣는다. 화면에 일부 줄만 보여 줄 때는 숨김 줄로 완전한 프로그램을 만든다. 예제 프로그램 전체는 빌드가 예제 목록 파일로 저장한다.
- **대본**
  - 장면 id는 `hook`, `extends`, `inherit`, `override`, `super`, `superctor`, `supermethod`, `single`, `outro` 정도로 둔다.
  - 영어 키워드는 한글 발음으로 쓴다(익스텐즈, 슈퍼, 오버라이드, 헬로).
  - 용어는 GLOSSARY를 따라 "부모 클래스·자식 클래스·오버라이딩"으로 쓰고, 상위·하위·슈퍼클래스·서브클래스는 쓰지 않는다. "재정의"는 화면에만 처음 한 번 병기한다.
- **README**: 제목은 "자바 입문: 클래스의 상속 (extends · 오버라이딩 · super() · super.메소드 · 단일 상속)"으로 한다. YouTube URL은 업로드 후 넣는다.

## Testing Decisions

- **좋은 테스트의 기준**: 시청자가 화면에서 보는 결과를 검사한다. 즉 예제의 실제 출력과 실제 컴파일 오류가 대본의 기대값과 같은지 본다. 빌드 스크립트 내부 구조나 HTML 마크업은 검사하지 않는다.
- **테스트 지점은 하나**: 기존 빌드 과정의 Java 예제 검증을 그대로 쓴다. 빌드는 장면마다 예제를 실제 JDK로 컴파일·실행한다. 출력이 기대값과 다르거나, 오류 예제가 기대한 컴파일 오류를 내지 않으면 멈춘다. 새 테스트 지점은 만들지 않는다.
- **빌드 이후 검증** (기존 절차)
  - HyperFrames check: 오류 0건, 레이아웃 겹침·넘침 없음. `line_unread` 경고는 허용한다.
  - snapshot: 모든 장면을 확인하고, 가장 빽빽한 장면을 390px 폭으로 줄여 모바일 가독성을 확인한다.
  - 자막: 대사 중 자막 없는 시간이 0초인지 확인한다.
  - 렌더링 후 ffprobe: 1080×1920, 오디오 트랙 존재.
- **수동 검토**: 나레이션 문장이 화면의 기대 결과와 같은지 직접 확인한다. 자동 대조는 예제 결과까지만 하기 때문이다. 예: "민수 안녕이 나와요", "부모 생성자가 먼저 실행돼요".
- **참고할 기존 사례**: 직전 두 Java 영상(클래스와 객체, 메소드와 생성자)의 출력 대조·컴파일 오류 대조 예제. 특히 지난 영상의 "기본 생성자 주의" 장면이 4-1과 같은 형태다.

## Out of Scope

- 다형성(부모 타입 변수에 자식 객체 담기), 형변환, `instanceof`
- `Object` 클래스와 `toString()`·`equals()` 오버라이딩
- 접근 제어자(`private`·`protected`·`public`)와 상속 시 접근 범위
- 여러 단계 상속(A → B → C), 인터페이스, 추상 클래스, `final`
- `@Override` 오타 오류 예시
