# 01: 프로젝트 골격 + 대본 전체 + 도입·STEP 1 왜 필요한가

**What to build:** 래퍼 클래스와 List 편(17편)과 같은 방식·템포(1.2배)로 "람다식" 영상 프로젝트를 만든다. 상단 바 브랜드는 "자바 람다식 정리"로 하고 "람다식"을 주황으로 강조한다. 진행 표시는 5칸이다(2-1→2, 3-1→3, 4-1·4-2→4, 5-1→5).

17편의 컴파일·실행 대조 헬퍼(출력 대조)와 컴파일 오류 대조 헬퍼를 그대로 가져온다. 한 가지를 넓힌다.
- **컴파일만 확인**: 출력이 없는 코드 조각(02의 줄여 쓰기 조각)을 숨긴 `main`으로 감싸 컴파일만 되는지 확인할 수 있게 한다. 컴파일 오류가 나면 빌드를 멈춘다

이 티켓에서 **영상 전체 대본**을 먼저 쓰고 길이(3분 이하)를 확인한다. 그 다음 도입과 STEP 1을 대본 → 음성 → 화면까지 만든다.
- hook: "자바 입문 열여덟 번째, 람다식". 큰 제목 `s -> s >= 80`(`->` 주황)
- why: `interface Checker { boolean check(int s); }`를 구현 클래스(`implements`, 13편)로 만든 여러 줄 코드 → `Checker c = s -> s >= 80;` 한 줄로 비교. `c.check(85)`, `c.check(78)` → `true false`. 람다식도 함수형 인터페이스를 구현한 객체를 만든다는 것을 말한다(익명 클래스는 언급하지 않는다)

이 장면들만으로 볼 수 있는 빌드가 나와야 한다.
