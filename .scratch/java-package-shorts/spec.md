# 스펙: 자바 입문 열다섯 번째 — 패키지

Status: resolved

## Problem Statement

자바 입문 시리즈 시청자는 지금까지 모든 클래스를 `Main.java` 하나, 즉 한 곳에 몰아 넣고 썼다. 하지만 실제 프로젝트나 IDE에서 만든 코드를 열면 맨 위에 `package`와 `import`가 있고, 클래스는 여러 폴더에 나뉘어 있다. 시청자는 이것이 무엇인지 아직 모른다.

입문자가 패키지에서 특히 자주 헷갈리는 점은 다음과 같다.

- `package school;`이 무엇이고 폴더와 어떤 관계인지
- 다른 패키지의 클래스를 쓰는 방법, 그리고 `import`가 실제로 하는 일(클래스를 복사하는 것이 아니라 이름을 줄여 쓰게 해 줄 뿐)
- 패키지를 나누자마자 생기는 `is not public in school` 오류
- `String`·`System`은 import 없이 쓰는데 `Arrays`는 왜 import해야 하는지
- 이름이 같은 클래스(`java.util.Date`와 `java.sql.Date`)를 함께 쓰는 방법

3분 이하 세로 쇼츠 한 편으로, 실제로 여러 파일을 컴파일·실행하는 예제를 써서 이 내용을 정확히 보여 줄 영상이 필요하다.

## Solution

시리즈 열다섯 번째 영상 "패키지"를 기존 영상과 같은 디자인·제작 방식으로 만든다.

- 영상 규격: 1080×1920, 약 2분 30초, 1.2배 템포
- 예시 클래스: 14편의 `Person`·`Student`(민수·85)·`Teacher`(서준)를 `school` 패키지로 옮긴다. 이를 쓰는 `Main`은 `app` 패키지에 둔다.
- 흐름: package 선언 → 전체 이름 → import → public 필요 → 표준 라이브러리 → java.lang → 같은 이름 클래스

장면 구성은 아래와 같다.

| id | 장면 | 진행 표시 | 내용 |
|---|---|---|---|
| hook | 도입 | – | 자바 입문 열다섯 번째, 패키지 |
| decl | 1. package 선언 | 1 | `package school;` + 파일 트리(`school/Person.java`·`Student.java`·`Teacher.java`, `app/Main.java`). 패키지 이름과 폴더를 맞춰 둔다. 메모: 실무 관례 `com.example.school`(소문자, 도메인을 거꾸로) |
| full | 2. 전체 이름 | 2 | `app/Main.java`에서 `school.Student s = new school.Student("민수", 85);` → `s.hello()` → `학생 민수 안녕` |
| imp | 2-1. import | 2 | `import school.Student;` 후 `Student`만으로 같은 결과 `학생 민수 안녕`. import는 이름을 줄여 쓰게 해 줄 뿐 |
| pub | 3. public 필요 | 3 | `public`이 없는 `class Student` → 다른 패키지에서 컴파일 오류. 생성자·메소드도 다른 패키지에서 쓰려면 `public`(해당 줄 `mark`). 메모: public 클래스는 파일 이름과 같아야 함(`Student.java`) |
| std | 4. 표준 라이브러리 | 4 | `import java.util.Arrays;` → `{85, 90, 70}` 정렬 → `[70, 85, 90]`. 메모: `import java.util.*;`는 그 패키지의 클래스를 모두 |
| lang | 4-1. java.lang | 4 | `String`·`System`은 `java.lang` 패키지라 import 없이 씀. `java.lang.String`으로 써도 같다 → `민수` |
| clash | 5. 같은 이름 클래스 | 5 | `java.util.Date`와 `java.sql.Date`를 둘 다 import → 컴파일 오류. 하나는 import하고 하나는 전체 이름으로 → `2026-11-16` |
| outro | 정리 | – | 6줄 목록, 나레이션에 맞춰 줄 강조, 👍 구독 · 좋아요 |

## User Stories

1. 시청자로서, 첫 화면에서 "자바 입문 열다섯 번째, 패키지"라는 주제를 바로 알고 싶다. 따라오던 시리즈의 다음 편인지 알 수 있기 때문이다.
2. 시청자로서, 지난 편의 `Person`·`Student`·`Teacher`, 민수가 다시 나오길 바란다. 새 예제를 익히는 부담 없이 패키지 개념에만 집중할 수 있기 때문이다.
3. 시청자로서, 파일 맨 위의 `package school;` 한 줄을 보고 싶다. IDE가 만들어 주는 그 줄이 무엇인지 알 수 있기 때문이다.
4. 시청자로서, `school` 패키지의 클래스가 `school/` 폴더에 있는 파일 트리를 보고 싶다. 패키지 이름과 폴더 구조를 맞춘다는 것을 눈으로 확인할 수 있기 때문이다.
5. 시청자로서, 패키지를 "클래스를 묶는 이름"으로 설명 듣고 싶다. 폴더와 같은 것인지 헷갈리지 않기 때문이다.
6. 시청자로서, 실무에서는 `com.example.school`처럼 소문자와 도메인을 거꾸로 쓴 이름을 쓴다는 메모를 보고 싶다. 다른 사람의 코드에서 보는 긴 패키지 이름을 알아볼 수 있기 때문이다.
7. 시청자로서, 다른 패키지(`app`)의 `Main`에서 `school.Student`라고 써서 객체를 만드는 것을 보고 싶다. 다른 패키지의 클래스를 쓰는 가장 기본적인 방법을 알 수 있기 때문이다.
8. 시청자로서, `school.Student` 같은 표기를 "전체 이름"이라 부르고, 화면에 "(패키지 이름 + 클래스 이름)"이 함께 적혀 있길 바란다. 용어와 뜻을 함께 기억할 수 있기 때문이다.
9. 시청자로서, 전체 이름으로 만든 민수 객체가 `학생 민수 안녕`을 출력하는 것을 보고 싶다. 패키지를 나눠도 코드가 그대로 동작한다는 것을 확인할 수 있기 때문이다.
10. 시청자로서, `import school.Student;`를 적으면 `Student`만으로 쓸 수 있다는 것을 보고 싶다. 매번 긴 이름을 쓰지 않는 방법을 알 수 있기 때문이다.
11. 시청자로서, import 뒤에도 출력이 `학생 민수 안녕`으로 똑같다는 것을 보고 싶다. import가 이름만 줄여 줄 뿐 동작을 바꾸지 않는다는 것을 결과로 알 수 있기 때문이다.
12. 시청자로서, import가 클래스를 복사하거나 포함하는 것이 아니라는 설명을 듣고 싶다. 흔한 오해를 처음부터 피할 수 있기 때문이다.
13. 시청자로서, `Student` 클래스에 `public`이 없으면 다른 패키지에서 컴파일 오류가 나는 것을 보고 싶다. 패키지를 나누자마자 가장 먼저 부딪치는 오류를 미리 알 수 있기 때문이다.
14. 시청자로서, 실제 오류 문구 `is not public in school`을 화면에서 보고 싶다. 직접 같은 오류를 만났을 때 알아볼 수 있기 때문이다.
15. 시청자로서, 생성자와 메소드도 다른 패키지에서 쓰려면 `public`이 필요하다는 것을 듣고, 코드에서 그 줄들이 강조되길 바란다. 클래스에만 붙이면 끝나는 줄 아는 실수를 피할 수 있기 때문이다.
16. 시청자로서, 접근 범위는 다음 편에서 자세히 다룬다는 말을 듣고 싶다. 이번 편의 범위를 알고 다음 편을 기대할 수 있기 때문이다.
17. 시청자로서, public 클래스는 파일 이름과 같아야 한다는 메모를 보고 싶다. 파일 이름 때문에 생기는 오류를 피할 수 있기 때문이다.
18. 시청자로서, 자바가 미리 만들어 둔 `java.util.Arrays`를 import해서 쓰는 것을 보고 싶다. 표준 라이브러리도 패키지로 묶여 있다는 것을 알 수 있기 때문이다.
19. 시청자로서, `Arrays.sort`로 `{85, 90, 70}`이 `[70, 85, 90]`이 되는 것을 보고 싶다. 이미 만들어진 기능을 가져다 쓰는 장점을 결과로 확인할 수 있기 때문이다.
20. 시청자로서, `import java.util.*;`가 그 패키지의 클래스를 모두 쓰게 해 준다는 메모를 보고 싶다. 다른 코드에서 자주 보는 모양을 알아볼 수 있기 때문이다.
21. 시청자로서, `String`·`System`은 `java.lang` 패키지라서 import 없이 쓴다는 설명을 듣고 싶다. 지금까지 import 없이 써 온 이유를 알 수 있기 때문이다.
22. 시청자로서, `java.lang.String`으로 써도 같은 결과(`민수`)가 나오는 것을 보고 싶다. java.lang도 다른 패키지와 같은 원리라는 것을 확인할 수 있기 때문이다.
23. 시청자로서, 이름이 같은 `java.util.Date`와 `java.sql.Date`를 둘 다 import하면 컴파일 오류가 나는 것을 보고 싶다. 같은 이름 클래스가 실제로 부딪친다는 것을 알 수 있기 때문이다.
24. 시청자로서, 하나는 import하고 하나는 전체 이름으로 쓰면 둘 다 쓸 수 있다는 것을 보고 싶다. 이름 충돌을 푸는 방법을 알 수 있기 때문이다.
25. 시청자로서, `java.sql.Date.valueOf("2026-11-16")`가 `2026-11-16`을 출력하는 것을 보고 싶다. 전체 이름으로 쓴 코드도 제대로 동작한다는 것을 결과로 확인할 수 있기 때문이다.
26. 시청자로서, 정리 장면에서 여섯 가지 핵심을 목록으로 한꺼번에 보고, 나레이션이 말하는 줄이 강조되길 바란다. 복습하면서 따라 읽을 수 있기 때문이다.
27. 시청자로서, 모든 자막이 나레이션과 단어 단위로 맞길 바란다. 소리 없이 보더라도 내용을 따라갈 수 있기 때문이다.
28. 시청자로서, 휴대폰 화면에서도 파일 트리와 코드가 읽히길 바란다. 쇼츠는 대부분 휴대폰으로 보기 때문이다.
29. 제작자로서, 화면의 모든 예제가 실제 폴더 구조로 여러 파일을 컴파일·실행해서 대본의 결과와 같은지 빌드가 확인하길 바란다. 한 파일로 흉내 낸 예제는 패키지 동작을 증명하지 못하기 때문이다.
30. 제작자로서, 화면에 나오는 컴파일 오류 문구도 빌드가 실제 javac 결과와 대조하길 바란다. 틀린 오류 문구를 올리는 일을 막을 수 있기 때문이다.

## Implementation Decisions

- **새 영상 프로젝트**: `java-package-shorts`. 14편(다형성)의 음성 생성 스크립트와 빌드 스크립트를 복사해 만든다(템포 1.2배, TTS `+34%`). 디자인 토큰·글꼴·화면 구성·모션은 바꾸지 않는다.
- **상단 바 브랜드**: "자바 입문 패키지 정리", "패키지"는 주황 강조. 진행 표시는 5칸이다. 2-1은 2번째 칸, 4-1은 4번째 칸에 속한다.
- **예시 데이터** (영상 전체에서 하나로 통일)
  - `school` 패키지
    - `Person` (k1): `public abstract class`. `String name`, `public` 생성자, `public abstract void hello()`
    - `Student` (k2): `public class Student extends Person`. `int score`, `public` 생성자, `public void hello()` → `"학생 " + name + " 안녕"`. 객체는 민수·85.
    - `Teacher` (k3): `public class Teacher extends Person`. `public void hello()` → `name + " 선생님 안녕"`. 파일 트리에만 나오고 예제에서는 쓰지 않는다.
  - `app` 패키지: `public class Main`. 모든 예제 문장은 이 클래스의 `main` 안에서 실행된다.
  - 14편의 `Studyable`·`Teachable` 인터페이스는 이번 편에서 쓰지 않는다.
  - 파일 트리, 패키지 이름, 화면의 객체·출력 줄은 대상별 색(Person k1, 민수 k2, 서준 k3)을 유지한다.
- **장면별 기대 결과** (기획 단계에서 로컬 javac/java 25로 확인함)
  - decl: 컴파일 성공(파일 묶음 전체)
  - full: `학생 민수 안녕`
  - imp: `학생 민수 안녕`
  - std: `[70, 85, 90]`
  - lang: `민수`
  - clash: `2026-11-16`. `java.util.Date`는 선언만 하고 출력하지 않는다(실행 시각에 따라 달라지므로).
  - 컴파일 오류 예제와 javac 오류 문구(대조 기준)
    - pub: `Student is not public in school; cannot be accessed from outside package`
    - clash(둘 다 import): `a type with the same simple name is already defined by the single-type-import of Date`
- **여러 파일 컴파일 헬퍼**: 기존 빌드의 Java 실행 헬퍼는 `Main.java` 한 파일만 컴파일한다. 이를 "경로 → 소스"로 된 파일 묶음을 받도록 넓힌다. 묶음 전체를 폴더 구조 그대로 임시 디렉터리에 쓰고, 한 번에 컴파일한 뒤 `app.Main`을 실행한다. 출력 대조, 컴파일 오류 대조, 예제 기록(`examples.txt`, 파일별로 기록)의 인터페이스는 기존 헬퍼와 같은 모양으로 유지한다. 장면마다 기본 묶음(`school` 3개 + `app.Main`)에서 바뀐 파일만 넘긴다.
- **사실 표현 주의**
  - "패키지 = 폴더"를 컴파일러가 강제하는 절대 규칙처럼 말하지 않는다. javac는 소스를 직접 지정하면 폴더가 달라도 컴파일한다(로컬에서 확인함). 대본은 "패키지 이름과 폴더를 맞춰 둔다, 자바가 클래스를 찾는 기준이다"처럼 쓴다.
  - pub 장면은 "다른 패키지에서 쓰려면 `public`"까지만 말한다. `public`이 없을 때의 접근 범위(같은 패키지에서만)는 한 문장으로 언급하고, 자세한 내용은 16편으로 넘긴다.
- **장면 구성 요소**
  - decl은 코드 한 줄과 파일 트리를 함께 보여 준다. 트리는 기존 `.list`·`.chips` 스타일을 재사용하거나 코드 블록 모양으로 그린다. 새 디자인 토큰은 추가하지 않는다. 관례 이름은 `.note` 한 줄로 둔다.
  - full은 `school.Student` 부분을 주황으로 강조하고, "전체 이름 (패키지 이름 + 클래스 이름)"을 표시한다.
  - full과 imp는 같은 결과가 나온다는 것이 보이도록 같은 모양으로 배치한다(imp의 `import` 줄을 `mark`로 강조).
  - pub는 오류 예제와 실제 오류 문구, `.warn`, 그리고 `public` 생성자·메소드 줄을 `mark`로 강조한 코드를 보여 준다. 파일 이름 규칙은 `.note`로 둔다.
  - std는 `*` import를 `.note` 한 줄로 둔다.
  - clash는 오류 예제(두 import)와 해결 코드(하나는 전체 이름)를 차례로 보여 준다. 화면이 좁으면 오류 예제는 import 두 줄과 오류 문구만 보여 준다.
  - 코드 한 줄은 33자 이하로 쓴다. `java.sql.Date day = java.sql.Date.valueOf(...)`는 `=` 뒤에서 줄을 바꾼다.
- **대본**
  - 영어 키워드는 한글 발음으로 쓴다(패키지, 임포트, 스쿨, 앱, 퍼블릭, 어레이즈, 소트, 투스트링, 자바 유틸, 자바 랭, 자바 에스큐엘, 데이트, 밸류오브, 스튜던트, 헬로).
  - 용어는 GLOSSARY를 따른다: 패키지, import, 전체 이름. "풀 네임", "정규화된 이름", "불러오기(단독 표기)"는 쓰지 않는다.
  - 길이는 대본 전체를 먼저 써서 확인하고, 3분을 넘으면 음성 생성 전에 줄인다.
- **정리 장면 6줄**
  1. `package`로 클래스를 묶고 폴더와 맞춘다
  2. 전체 이름 = 패키지 이름 + 클래스 이름
  3. `import`로 이름을 줄여 쓴다
  4. 다른 패키지에서 쓰려면 `public`
  5. `java.lang`은 import 없이
  6. 같은 이름 클래스는 하나를 전체 이름으로

## Out of Scope

- 접근 제어자 4종(`private`·default·`protected`·`public`) 비교, 메소드·생성자·필드의 접근 범위 → 16편 "접근 제어자"
- `static import`
- 명령줄 컴파일·실행(`javac -d`, `java app.Main`, 클래스패스)
- `*` import의 함정(하위 패키지 미포함, 두 `*` import의 이름 모호 오류)
- 모듈(`module-info.java`), JAR
- 디자인·템포·제작 도구의 변경

## Further Notes

- 시리즈 순서: … → 인터페이스(13) → 다형성(14) → 패키지(15). 다음 편 후보는 접근 제어자(16).
- 지난 편들의 `Person`·`Student`에는 `public`이 없었다. 다른 패키지에서 쓰려면 클래스·생성자·메소드에 `public`이 필요해서 이번 편부터 붙인다. pub 장면이 그 이유를 설명한다.
- `Person.hello()`를 `public abstract`로 두면, `Student.hello()`에서 `public`을 뺐을 때 `cannot override` 오류가 난다(13편의 "더 좁힐 수 없음"과 같은 원리). 이번 편에서는 다루지 않는다.
- clash의 날짜 `2026-11-16`은 기획한 날이다.
- 용어 3개(패키지, import, 전체 이름)는 기획 단계에서 GLOSSARY에 등록했다.
- 커밋·푸시는 사용자가 요청할 때만 한다.
