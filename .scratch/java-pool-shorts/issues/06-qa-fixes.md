# 06: 질문 반영 고칠 리스트

**What to build:** 업로드 전 사용자 질문에서 나온 수정 사항을 모아 두고, 질문이 모두 끝나면 한 번에 음성 생성 → 빌드 → 검증·렌더링한다. 질문하는 동안에는 음성 생성·렌더링을 하지 않는다.

## 고칠 리스트

### 반영함 (파일 수정 완료, 렌더링 전)

- [x] **작업 큐(대기 줄)** — 질문: "먼저 끝난 스레드가 다음 작업을 맡는다면 작업 큐가 따로 있어야 하지 않나?"
  - 사실: `newFixedThreadPool`은 `ThreadPoolExecutor` + `LinkedBlockingQueue`(크기 제한 없음). 스레드가 정해 둔 개수보다 적으면 새 스레드에 바로 맡기고, 다 차면 큐에 넣는다. 작업을 끝낸 스레드가 큐에서 꺼내 간다
  - why 나레이션 끝 문장 → "작업 두 개를 먼저 맡고, 남은 작업은 대기 줄에서 기다리다가, 먼저 끝난 스레드가 꺼내 가요."
  - why 그림에 "대기 줄" 칸 추가(작업 3 점선 + "↓ 꺼내 감"), 메모 → "먼저 끝난 스레드가 대기 줄에서 꺼내 간다"
  - 주의: 이 대본으로 why 음성은 이미 한 번 다시 만들어짐(사용자가 멈추라고 하기 전)

- [x] **"22편" 발음** — 질문: TTS가 "22편"을 "스물두 편"으로 읽어 개수처럼 들림. 편 번호는 "이십이 편"으로 읽는 게 자연스럽다
  - 대본 두 곳을 한글 발음으로: hook "이십이 편에서는", submit "이십이 편처럼"(자막도 그대로 "이십이 편"으로 나옴). 순서를 말하는 "스물네 번째"는 그대로
  - 음성은 아직 다시 만들지 않음
  - 대본 전체에서 숫자가 들어간 곳을 다시 훑음: 남은 숫자는 submit "풀에 2를"뿐(괄호 안 숫자 2, "이를"로 읽혀야 맞음). 음성을 만든 뒤 이 부분이 "두를"로 읽히지 않는지 들어서 확인할 것
- [x] **학습 밀도** — 질문: 내용이 휙휙 넘어가서 학습에 도움이 될지. 영상은 그대로 두고 업로드 설명에 "📖 용어 정리"(스레드 풀·대기 줄, ExecutorService, newFixedThreadPool, 작업·Runnable·Callable, submit, Future, get, try-with-resources, 가상 스레드)를 추가함. 꺾쇠 없음 확인
