## 이번 작업이 오래 걸린 이유(추정)

이전 영상들은 하루에 커밋 하나로 끝났고 세션 시간 기록이 없어서, 직접 비교할 수는 없다. 아래는 이번 세션의 흐름에서 추정한 이유다.

1. **구현과 검사를 다른 모델로 나눠 왕복이 늘었다.** Sonnet이 구현하고 Opus가 스냅샷·대본을 검사해 되돌려 보내는 구조라서, 티켓마다 1~2번 재작업이 생겼다(총 6번).
   - 재작업 사유: 브랜드 문구, 나레이션의 영문 `int`, "에스원" 표기, `final` 구문 강조, 정리 장면 줄바꿈 등
   - 대부분 CLAUDE.md에 이미 적힌 규칙이었다. 처음부터 Opus가 구현했다면 피했을 수도 있는 것들이다.
2. **티켓이 일렬로만 진행돼 병렬 효과가 없었다.** 다섯 티켓이 모두 같은 `build.py`·`script.json`·음성을 고치므로 동시에 돌릴 수 없었다. 그래서 워크트리를 만들고 병합하는 비용만 더해졌다.
3. **새 워크트리마다 준비 작업을 반복했다.** mp3가 git에 없어서 에이전트마다 `gen_vo.py`로 전체 음성을 다시 만들었다. 컨텍스트(CLAUDE.md, 스펙, 이전 영상 코드)도 매번 처음부터 읽었다.
4. **영상 길이 문제를 늦게 발견했다.** 티켓별로 대본을 쓰면서 전체 길이 예산이 없었다.
   - 04에서 나레이션이 167초가 되어 3분 초과가 예상됐다.
   - 115초로 줄였다가, 필수 문장이 빠져 125.6초로 되돌렸다.
   - 그 과정에서 음성 재생성과 빌드를 두 번 더 했다.
5. **렌더링을 여러 번 했다.** 티켓 05에서 렌더링한 뒤, 정리 장면 수정과 리뷰 수정 때 다시 렌더링해 총 3번 했다.
6. **코드 리뷰 단계가 추가됐다.** `/implement-spec` 흐름에 따라 리뷰 에이전트 2개와 수정 에이전트 1개, 재렌더링이 더해졌다.
7. **에이전트 호출을 두 번씩 했다.** 훅이 서브에이전트 프롬프트를 고치는 바람에 auto 모드 검사가 첫 호출을 거부했다. 그래서 Agent 호출을 매번 두 번 보냈다(지연은 작다).
8. **기획 단계가 길었다.** `/grill-with-docs` 질문 3라운드, 스펙, 티켓 작성에만 약 17분이 들었다.
