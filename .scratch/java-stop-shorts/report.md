## 장면 구성 (최종)

| 장면 | 내용 | 빌드가 확인한 것 |
|---|---|---|
| 도입 | `t.stop()`은 이제 예외만 던져요 · "① 요청 ② 스스로" | `jrt`: JDK 25에서 `UnsupportedOperationException` |
| STEP 1 멈춤 신호 | `static volatile boolean stop` → `while (!stop)` → `stop = true` | `jmulti` 20회: `작업 중` 1줄 이상 + 마지막 `작업 끝` |
| STEP 2 인터럽트 | `while (true)` + `t.interrupt()` (두 줄 강조) | `jmulti` 20회 |
| STEP 3 예외 삼키지 않기 | 반복 안의 빈 `catch` → 끝나지 않음 / `catch` 안에서 `interrupt()`로 되살리기 | 빈 catch: `jhang`(3초 동안 안 끝나고 `작업 중` 8줄 이상, `작업 끝` 없음) / 고친 버전: `jmulti` 20회 |
| STEP 4 데몬 스레드 | `start()` 전에 `setDaemon(true)` → `main 끝` 뒤 프로그램 종료 | `jmulti` 20회 + `setDaemon`을 뺀 버전은 `jhang`(`main 끝` 뒤에도 계속 돎) |
| 정리 | 5줄, 나레이션에 맞춰 줄 강조 | 단어 시각(`word_time`) |

## 공용 모듈 변경 (`tools/javashorts.py`)

- 프로그램 실행 함수에 선택 인자 `timeout`을 추가했습니다. 기본값은 제한 없음이라 기존 동작은 그대로입니다.
- 새 헬퍼 `jhang(sid, lines, secs=3, each=)`를 만들었습니다. 정해진 시간 안에 **끝나지 않아야** 통과하고, 시간이 지나면 프로세스를 강제로 종료합니다. 그 사이의 출력은 `each`로 검사합니다.
- `docs/java-helpers.md`에 사용법을 적었습니다.
- 회귀 확인: `java-pool-shorts`·`java-thread-shorts`를 다시 빌드했고, 두 편 모두 `git diff`가 없었습니다. 헬퍼를 고칠 때마다 두 번 확인했습니다.

## 제작 중 직접 찾아 고친 것

1. **데몬 장면 출력 상자에 "(출력 없음)"이 그려짐**: `jhang`이 마지막 실행 결과(`LAST`)를 비운 뒤에 출력 상자가 그려져서 생긴 문제입니다. `jhang`이 `LAST`를 건드리지 않게 헬퍼를 고쳤습니다.
2. **화면 높이 초과**: 처음 설계대로 그리면 코드 15줄과 출력 6줄이 자막 영역까지 내려왔습니다. 그래서 메모를 desc로 올리고, main의 마지막 줄들은 출력 상자 옆에 "이어서 main" 칸으로 나눠 그렸습니다. 이 영상에서만 코드 줄 간격을 1.4로 줄였습니다.
3. **출력 줄 수가 흔들릴 수 있음**: 1초와 0.2초 간격이 겹쳐서 `작업 중`이 5줄일 때도 6줄일 때도 있습니다. 그래서 검사는 줄 수를 고정하지 않고, "1줄 이상 + 마지막 줄"만 봅니다.

- `volatile`, `interrupt`, 인터럽트 상태가 지워지는 동작, `setDaemon`은 `start()` 전에 불러야 한다는 점
- 22편·24편 인용이 실제 대본과 일치함
- 예제 검사가 출력 줄 수에 따라 흔들리지 않음
- `timeout` 기본값이 기존 영상에 영향을 주지 않음
- 레이아웃, 썸네일, 유튜브 초안 형식
