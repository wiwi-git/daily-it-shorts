# 01: 프로젝트 골격 + 대본 전체 + 도입·STEP 1 메소드 전체를 잠그면

**What to build:** 22편(`java-thread-shorts`)과 같은 방식·템포(1.2배)로 `java-sync-shorts` 영상 프로젝트를 만든다. 음성 생성·빌드 스크립트를 복사해 장면만 바꾼다. 상단 바 브랜드는 `자바 입문 <em>동기화</em> 정리`이고, 진행 표시는 5칸이다(scope→1, block→2, atomic→3, list→4, outro→5).

이 티켓에서 **영상 전체 대본**(hook, scope, block, atomic, list, outro)을 먼저 쓰고 길이(목표 2분 30초 이하)를 음성으로 확인한다. 그다음 도입과 STEP 1을 대본 → 음성 → 화면까지 만든다. 나머지 장면은 제목만 있는 자리표시 화면으로 둔다.

- hook: "자바 입문 스물세 번째, 동기화 더 깊이". 150px 큰 제목 "동기화 <em>더 깊이</em>". 22편의 `synchronized`는 20000을 맞췄지만 문제가 하나 있었다
- scope: 22편과 같은 `static synchronized void inc()`(만 번 `count++`) 코드. `jmulti`로 매 실행 `20000`인지 검사. 그 아래 개념도: 가로 막대 두 줄로 스레드 1(k1)이 끝난 뒤에야 스레드 2(k2)가 이어지는 모습. 결과는 맞지만 사실상 순차 실행. 시간·숫자는 넣지 않는다(빌드 스크립트 안의 짧은 HTML, 디자인 토큰 색만)

자세한 결정은 [../spec.md](../spec.md).

## Comments

- 대본 전체 6장면, 음성 합계 120.9초 → 영상 124.0초(2:04). 01 단계에서는 block~list를 자리표시로 두었다가 02·03에서 채움.
- scope 개념도는 build.py 지역 CSS(`.tline`/`.trk`): 스레드 1 주황(k1) 막대 → 스레드 2 "기다림" 점선 + 초록(k2) 막대. 숫자·초 없음.
- `synchronized`는 공용 `J.KW`에 없어 강조되지 않았음 → build.py에서 `J.KW.append("synchronized")`로 이 영상에서만 추가(공용 모듈은 그대로, 22편 재빌드 결과 영향 없음).
- 진행 표시: 22편 등 기존 영상처럼 outro는 PROG에 넣지 않음(스펙 "outro→5"와 다름, 시리즈 관례 우선).
- 대본은 "잠금"을 단독으로 쓰지 않도록 "잠금 없이" 대신 "싱크로나이즈드 없이"로 씀(스펙의 같은 표현도 함께 고침).
- 검증: 기대값을 19999로 바꾸면 `scope: a run printed '20000\n', which the script's check rejects`로 멈춤. `tools/verify-video.sh java-sync-shorts --no-render` 통과.
