# 01: 여러 번 실행해 검증하는 헬퍼 `jmulti`

**What to build:** 실행할 때마다 순서·값이 달라지는 스레드 예제를 검증하는 헬퍼를 공용 모듈 `tools/javashorts.py`에 추가한다. 영상 프로젝트와 무관하게 먼저 끝낸다.

- `jmulti(sid, lines, shown, ...)`: 예제를 한 번 컴파일한 뒤 `runs`번(기본 20) 실행한다
- 검사는 두 갈래를 지원한다
  - 매 실행 출력 검사(예: 줄 묶음이 같다, 정확히 `20000`이다)
  - 전체 실행 출력을 모아 검사(예: 한 번 이상 20000 미만)
  - 이름·형태는 구현하면서 정한다(예: `ok_each`·`ok_all`)
- 하나라도 거짓이거나 컴파일 오류·실행 중 예외가 나면, 실제로 나온 출력과 함께 빌드를 멈춘다
- 화면 결과 상자는 실제 출력이 아니라 고정 예시 `shown`으로 그린다. 라벨은 인자로 바꿀 수 있다(기본 "실행 결과 예시")
- 예제 기록 파일(`examples.txt`)에는 "실행할 때마다 순서·값이 다름" 주석과, 이번 빌드에서 관찰한 출력 범위(예: 서로 다른 출력 몇 가지)를 남긴다
- `mark=`, `pre=`, `top=`, `members=` 등 기존 헬퍼와 같은 인자를 받는다
- `docs/java-helpers.md` 헬퍼 표에 한 줄 추가한다

## Comments

- 구현: `compile_()`·`exec_()`로 컴파일과 실행을 나누고(`run()`은 둘을 이어 부름, 동작 같음), `jmulti`·`same_lines` 추가. 검사 인자는 `each=`(매 실행)·`all_=`(전체 목록).
- 범위 조정: 티켓은 `examples.txt`에 "관찰한 출력 범위"를 남기자고 했지만, 그러면 빌드마다 파일이 바뀐다. 고정 예시 + "실행할 때마다 다를 수 있음" 주석만 남긴다.
- 검증: 실패 경로 4가지(매 실행 검사, 전체 검사, 화면 예시 검사, 실행 중 예외)가 모두 빌드를 멈춤. 21편·20편·19편을 다시 빌드해 `index.html`·`examples.txt`에 diff 없음.
- 관찰: 이번 테스트 20회 중 `main 끝`이 맨 앞에 나온 실행이 있었다. 기획 때 20회는 모두 같은 순서였으므로, start 장면 화면 예시(`민수 85 / main 끝 / 서준 92`)는 그대로 두되 순서가 실제로 바뀐다는 근거가 생겼다.
