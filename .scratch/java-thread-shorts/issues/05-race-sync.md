# 05: STEP 3 경쟁 조건 + STEP 4 `synchronized`

**What to build:** 같은 변수를 두 스레드가 바꾸면 값이 사라지고, 동기화로 고치는 두 장면.

- race: `static int count`를 두 스레드가 각각 10000번 `count++`하고, 둘 다 `join`한 뒤 출력
  - `jmulti`로 매 실행 20000 이하이고, 한 번 이상 20000 미만인지 검사
  - 화면 예시 `13426`, 라벨 "실행 결과 예시 · 매번 다름". 나레이션은 숫자를 말하지 않고 "이만보다 적게, 실행할 때마다 달라요"라고 한다
  - `count++`가 읽기·더하기·쓰기 세 단계라 겹치면 값이 사라진다는 것을 화면(작은 표나 메모)에 보여 준다
  - "경쟁 조건(레이스 컨디션)" 표기를 처음 한 번
- sync: `static synchronized void add() { count++; }`로 바꿔 스레드에서 `add()` 호출 → 매 실행 정확히 `20000`(`jmulti` 매 실행 검사). 한 번에 한 스레드만 들어간다고 설명한다

진행 표시는 race 3번째, sync 4번째 칸. 두 장면 모두 `main`에 `throws InterruptedException`.

## Comments

- 스펙과 달라진 형태: 33자 제한 때문에 람다 대신 메소드 참조 `new Thread(Main::inc)`(19편에서 배움)를 쓰고, `inc()`가 `count++`를 만 번 한다. sync는 `static synchronized void inc()` — 경쟁 조건 코드와 **단어 하나만** 다르다(스펙의 `add() { count++; }` 대신). 나레이션 "카운트를 올리는 메소드에 싱크로나이즈드"와 맞는다.
- race: `jmulti` 20회, 매번 ≤ 20000 + 한 번 이상 < 20000. 화면 `13426`(빨강), 메모 `count++ / 읽기→더하기→쓰기 / 같은 값을 읽고 각자 쓰면 → 하나 사라짐`, 경고 `경쟁 조건 (레이스 컨디션)`.
- sync: `jmulti` 20회 매번 `20000`. `jmulti`에 `note=` 인자를 추가해 examples.txt에 "20회 실행해 매번 같음 확인"으로 적는다(기본 문구는 "다를 수 있음"이라 맞지 않음). 21편 재빌드 diff 없음.
- 화면 수정: 처음 버전은 메모 줄바꿈이 어색하고 경고 둘째 줄이 자막에 가려서, 메모를 직접 줄바꿈하고 경고를 한 줄로 줄였다.
