# 스펙: 자바 입문 열일곱 번째 — 래퍼 클래스와 List

Status: resolved

## Problem Statement

시청자는 3편에서 배열을, 7편에서 향상된 for를 배웠다. 하지만 배열은 만들 때 크기가 정해져서, 학생이 몇 명이 될지 모를 때는 쓰기 불편하다. 실무 코드와 이후 편(18편 람다식, 19편 스트림)에는 `List`가 계속 나오는데, 시리즈에서는 아직 한 번도 다루지 않았다.

입문자가 List를 처음 쓸 때 특히 막히는 점은 다음과 같다.

- 숫자를 담으려고 `ArrayList<int>`를 쓰면 컴파일 오류가 난다. 꺾쇠 안에는 클래스 타입만 들어가므로 `Integer`를 써야 하는데, 래퍼 클래스가 무엇인지 모른다
- `Integer`와 `int`가 어떻게 자동으로 오가는지(오토박싱·언박싱), 그리고 `null`을 언박싱하면 실행 중 오류가 난다는 것
- 배열의 `arr[0]`·`.length`가 List에서는 `get(0)`·`size()`로 바뀐다는 것
- 하나를 지우면 뒤 칸이 앞으로 당겨져 인덱스가 바뀐다는 것
- `List<Integer>`에서 `remove(1)`은 값 1이 아니라 1번 칸을 지운다는 것
- 변수 타입을 왜 `ArrayList`가 아니라 `List`로 받는지(13·14편 인터페이스·업캐스팅과의 연결)

3분 이하 세로 쇼츠 한 편으로, 실제로 컴파일·실행한 결과와 오류로 이 내용을 정확히 보여 줄 영상이 필요하다.

## Solution

시리즈 열일곱 번째 영상 "래퍼 클래스와 List"를 기존 영상과 같은 디자인·제작 방식으로 만든다.

- 영상 규격: 1080×1920, 약 2분 30초, 1.2배 템포
- 흐름: 래퍼 클래스를 먼저 배우고, List를 배운 뒤, 마지막에 두 가지를 합쳐 `List<Integer>`로 점수를 모은다
- 예시 데이터: 시리즈에서 써 온 민수·서준·지우, 추가용 하은. 점수 85·92·78(7편 향상된 for 예제와 같은 값)

장면 구성은 아래와 같다.

| id | 장면 | 진행 표시 | 내용 |
|---|---|---|---|
| hook | 도입 | – | 자바 입문 열일곱 번째, 래퍼 클래스와 List. 학생 점수를 몇 명이 될지 모른 채 모으고 싶다 → 문제 칩 두 개: "배열은 크기 고정", "`<int>`는 안 됨" |
| wrap | 1. 래퍼 클래스 | 1 | 기본 타입을 객체로 감싼 클래스. 대응표(`int`→`Integer`, `char`→`Character` 강조, `double`→`Double`, `boolean`→`Boolean`, 나머지는 첫 글자만 대문자). 실제로 네 타입에 값을 담아 출력해 확인 |
| box | 2. 오토박싱·언박싱 | 2 | `Integer n = 85;`(오토박싱), `int m = n + 1;`(언박싱) → `86`. `Integer.parseInt("85")` → `85`(문자열을 숫자로). 래퍼는 객체라서 `null`을 담을 수 있다 |
| npe | 2-1. null 언박싱 | 2 | `Integer n = null; int m = n;` → 실행 중 오류 `NullPointerException`(`.warn`) |
| list | 3. ArrayList 기본 | 3 | `import java.util.ArrayList;`(15편 import 연결). `ArrayList<String> names = new ArrayList<>();`, `add` 세 번 → `[민수, 서준, 지우]`, `size()` → `3`, `get(0)` → `민수`. 배열의 `arr[0]`·`.length`와 나란히 비교. 꺾쇠 안 = 담을 타입(제네릭) |
| idx | 3-1. 범위 밖 | 3 | `names.get(3)` → 실행 중 오류 `IndexOutOfBoundsException: Index 3 out of bounds for length 3`. 인덱스가 0부터인 건 배열과 같다 |
| edit | 4. set·remove·contains | 4 | `add("하은")` → `[민수, 서준, 지우, 하은]`, `remove(0)` → `[서준, 지우, 하은]`, `get(0)` → `서준`, `contains("민수")` → `false`, `set(0, "민수")` → `[민수, 지우, 하은]`. 지우기 전·후 인덱스 표로 뒤 칸이 당겨지는 것을 보여 준다 |
| nums | 5. List\<Integer\>로 점수 모으기 | 5 | `ArrayList<int>` → 컴파일 오류(`.warn`) → `List<Integer> scores = new ArrayList<>();`, `add(85)`·`add(92)`·`add(78)`, 향상된 for로 합계 → `255`(꺼낼 때 자동 언박싱). 변수 타입은 `List`로 받는다(`.note`: 14편 업캐스팅, `List`는 인터페이스·`ArrayList`는 구현 클래스) |
| rm | 5-1. remove(1)의 함정 | 5 | `[85, 92, 78]`에서 `scores.remove(1)` → `[85, 78]`(값 1이 아니라 1번 칸). 값을 지우려면 `scores.remove(Integer.valueOf(85))` → `[92, 78]` |
| outro | 정리 | – | 목록 전체 → 나레이션에 맞춰 줄 강조 → 👍 구독 · 좋아요 |

## User Stories

1. 시청자로서, 첫 화면에서 "자바 입문 열일곱 번째, 래퍼 클래스와 List"라는 주제를 바로 알고 싶다. 시리즈의 다음 편인지 알 수 있기 때문이다.
2. 시청자로서, 도입에서 "학생이 몇 명일지 모른다"는 상황을 먼저 보고 싶다. List가 왜 필요한지 납득한 뒤 배울 수 있기 때문이다.
3. 시청자로서, 도입의 문제 칩 두 개("배열은 크기 고정", "`<int>`는 안 됨")를 보고 싶다. 이번 편이 풀 두 문제를 한눈에 알 수 있기 때문이다.
4. 시청자로서, 래퍼 클래스가 "기본 타입을 객체로 감싼 클래스"라는 한 문장 정의를 듣고 싶다. 이름의 뜻과 함께 기억할 수 있기 때문이다.
5. 시청자로서, 기본 타입과 래퍼 클래스의 대응표를 보고 싶다. 어떤 래퍼를 써야 하는지 바로 찾을 수 있기 때문이다.
6. 시청자로서, `int`→`Integer`, `char`→`Character` 두 가지가 예외적인 이름이라는 것을 강조해서 보고 싶다. 나머지는 첫 글자만 대문자라 외울 것이 둘뿐이기 때문이다.
7. 시청자로서, `Integer n = 85;`처럼 숫자를 바로 담을 수 있다는 것을 보고 싶다. 래퍼 클래스를 쓰는 게 어렵지 않다는 것을 알 수 있기 때문이다.
8. 시청자로서, `int m = n + 1;`이 `86`을 출력하는 것을 보고 싶다. 래퍼 값으로 계산할 때 자동으로 기본 타입이 된다는 것을 결과로 확인할 수 있기 때문이다.
9. 시청자로서, 오토박싱과 언박싱이 각각 어느 방향의 자동 변환인지 화살표로 보고 싶다. 두 용어를 헷갈리지 않기 때문이다.
10. 시청자로서, `Integer.parseInt("85")`로 문자열을 숫자로 바꾸는 것을 보고 싶다. 래퍼 클래스가 쓸모 있는 메소드도 갖고 있다는 것을 알 수 있기 때문이다.
11. 시청자로서, 래퍼는 객체라서 `null`을 담을 수 있다는 것을 듣고 싶다. 기본 타입과의 차이를 알 수 있기 때문이다.
12. 시청자로서, `null`을 언박싱하면 `NullPointerException`이 나는 것을 실제 오류로 보고 싶다. 직접 같은 오류를 만났을 때 원인을 알아볼 수 있기 때문이다.
13. 시청자로서, `ArrayList`를 쓰려면 `import java.util.ArrayList;`가 필요하다는 것을 보고 싶다. 15편에서 배운 import와 이어지기 때문이다.
14. 시청자로서, `new ArrayList<>()`로 빈 리스트를 만들고 `add`로 하나씩 넣는 모습을 보고 싶다. 크기를 미리 정하지 않아도 된다는 것을 알 수 있기 때문이다.
15. 시청자로서, 리스트를 출력하면 `[민수, 서준, 지우]`처럼 보인다는 것을 보고 싶다. 배열과 달리 바로 내용을 확인할 수 있기 때문이다.
16. 시청자로서, 꺾쇠 `< >`로 "담을 타입"을 정하는 문법을 제네릭이라고 부른다는 설명을 듣고 싶다. 용어에 겁먹지 않고 뜻부터 이해할 수 있기 때문이다.
17. 시청자로서, 배열의 `arr[0]`·`.length`와 리스트의 `get(0)`·`size()`를 나란히 보고 싶다. 이미 아는 것에 대응시켜 빨리 익힐 수 있기 때문이다.
18. 시청자로서, 인덱스가 0부터 시작하는 건 배열과 같다는 것을 듣고 싶다. 새로 외울 것이 줄어들기 때문이다.
19. 시청자로서, 범위를 벗어난 `get(3)`이 `IndexOutOfBoundsException`을 내는 것을 실제 오류 문구로 보고 싶다. 배열의 인덱스 오류(3편)와 같은 개념임을 알 수 있기 때문이다.
20. 시청자로서, `add("하은")`으로 네 번째 학생이 자연스럽게 추가되는 것을 보고 싶다. 크기가 알아서 늘어난다는 것을 결과로 확인할 수 있기 때문이다.
21. 시청자로서, `remove(0)` 뒤에 뒤 칸이 한 칸씩 앞으로 당겨지는 것을 지우기 전·후 표로 보고 싶다. 배열과 가장 다른 점을 눈으로 이해할 수 있기 때문이다.
22. 시청자로서, 지운 뒤 `get(0)`이 `서준`을 돌려주는 것을 보고 싶다. 인덱스가 바뀐다는 것을 실제 값으로 확인할 수 있기 때문이다.
23. 시청자로서, `contains("민수")`가 `false`를 돌려주는 것을 보고 싶다. 값이 들어 있는지 확인하는 방법을 알 수 있기 때문이다.
24. 시청자로서, `set(0, "민수")`로 한 칸의 값을 바꾸는 것을 보고 싶다. 배열의 `arr[0] = 값`에 대응하는 방법을 알 수 있기 때문이다.
25. 시청자로서, 같은 학생은 모든 장면에서 같은 색으로 보고 싶다. 칸이 당겨질 때 누가 어디로 갔는지 따라갈 수 있기 때문이다.
26. 시청자로서, `ArrayList<int>`가 컴파일 오류라는 것을 실제 오류 문구로 보고 싶다. 도입에서 던진 질문의 답을 확인할 수 있기 때문이다.
27. 시청자로서, 꺾쇠 안에는 클래스 타입만 들어가서 `Integer`를 쓴다는 설명을 듣고 싶다. 래퍼 클래스를 배운 이유가 연결되기 때문이다.
28. 시청자로서, `add(85)`처럼 `int`를 그대로 넣어도 된다는 것을 보고 싶다. 오토박싱이 리스트에서도 일어난다는 것을 알 수 있기 때문이다.
29. 시청자로서, 7편에서 배운 향상된 for로 점수 합계 `255`를 구하는 것을 보고 싶다. 배운 문법을 리스트에도 그대로 쓸 수 있다는 것을 알 수 있기 때문이다.
30. 시청자로서, 변수 타입을 `List`로 받는 이유를 14편 업캐스팅과 연결해 듣고 싶다. 실무 코드에서 `List<...> x = new ArrayList<>()`를 봤을 때 이해할 수 있기 때문이다.
31. 시청자로서, `List`는 인터페이스이고 `ArrayList`는 그 구현 클래스라는 것을 보고 싶다. 13편 인터페이스와 이어서 이해할 수 있기 때문이다.
32. 시청자로서, `List<Integer>`에서 `remove(1)`이 `92`를 지워 `[85, 78]`이 되는 것을 보고 싶다. 값 1을 지울 거라는 오해를 바로잡을 수 있기 때문이다.
33. 시청자로서, 값으로 지우려면 `remove(Integer.valueOf(85))`를 쓴다는 것과 그 결과 `[92, 78]`을 보고 싶다. 함정을 피하는 방법까지 알 수 있기 때문이다.
34. 시청자로서, 정리 장면에서 오늘 배운 내용을 한 화면에 보고 싶다. 영상을 다시 보지 않아도 복습할 수 있기 때문이다.
35. 시청자로서, 나레이션이 말하는 순간 정리 항목이 강조되길 바란다. 어디를 읽어야 할지 따라갈 수 있기 때문이다.
36. 시청자로서, 화면의 모든 출력과 오류가 실제로 실행한 결과이길 바란다. 직접 따라 쳤을 때 같은 결과가 나와야 믿을 수 있기 때문이다.
37. 시청자로서, 휴대폰 화면에서도 코드와 표를 읽을 수 있길 바란다. 쇼츠는 주로 휴대폰으로 보기 때문이다.
38. 시청자로서, 나레이션과 단어 단위로 맞는 한국어 자막을 보고 싶다. 소리 없이 봐도 이해할 수 있기 때문이다.
39. 시청자로서, 정리 장면에서 "List에서 람다·스트림으로 이어진다"는 예고를 듣고 싶다. 다음 편을 기대할 수 있기 때문이다.
40. 제작자로서, 화면의 결과가 대본과 다르면 빌드가 멈추길 바란다. 틀린 내용을 올리는 실수를 막을 수 있기 때문이다.

## Implementation Decisions

- **새 영상 프로젝트**: `java-wrapper-list-shorts`. 16편(접근 제어자)의 음성 생성 스크립트와 빌드 스크립트를 복사해 만든다(템포 1.2배, TTS `+34%`). 디자인 토큰·글꼴·화면 구성·모션은 바꾸지 않는다.
- **상단 바 브랜드**: "래퍼 클래스와 List 정리", "List"는 주황 강조. 진행 표시는 5칸이다. 2-1은 2번째 칸, 3-1은 3번째 칸, 5-1은 5번째 칸에 속한다.
- **용어** (GLOSSARY): 래퍼 클래스, 오토박싱 / 언박싱, 리스트, ArrayList, 담을 타입. 기존 용어 업캐스팅·구현 클래스·인터페이스·import를 그대로 쓴다.
  - "제네릭"은 꺾쇠로 담을 타입을 정하는 **문법**의 이름으로 처음 한 번만 소개한다(정한 타입만 넣을 수 있다). 꺾쇠 안의 타입 자체를 제네릭이라 부르지 않는다
  - "포장 클래스", "동적 배열", "타입 매개변수", "자동 형변환"은 쓰지 않는다
- **예시 데이터** (영상 전체에서 하나로 통일)
  - 이름: 민수(k1), 서준(k2), 지우(k3), 하은(색 클래스 없음, 기본 글자색)
  - 점수: 85, 92, 78. `scores` 리스트의 순서도 이 순서다
  - 지우기 전·후 표에서 학생 색은 인덱스가 아니라 사람을 따라간다(칸이 당겨져도 서준은 계속 k2). 지운 민수의 칸은 `out`(취소선)
- **장면별 기대 결과** (기획 단계에서 로컬 javac/java로 확인함, 대조 기준)
  - 출력
    - wrap: 네 래퍼 변수에 담은 값의 출력(대본 작성 때 값 확정)
    - box: `86`(`n + 1`), `85`(`parseInt("85")`). 계산 결과를 보여 줘 문자열이 아니라 숫자가 됐음을 드러낸다(예: `parseInt("85") + 1` → `86`)
    - list: `[민수, 서준, 지우]`, `3`, `민수`
    - edit: `[민수, 서준, 지우, 하은]` → `[서준, 지우, 하은]`, `서준`, `false`, `[민수, 지우, 하은]`
    - nums: `255`
    - rm: `[85, 78]`, `[92, 78]`(각각 새 리스트 `[85, 92, 78]`에서 시작)
  - 컴파일 오류(첫 오류와 그 아래 설명 줄)
    - nums: `unexpected type`, 설명 줄 `required: reference`(화면에는 "꺾쇠 안에는 클래스 타입만"으로 풀어 쓰고, 원문은 작게 보여 준다)
  - 실행 중 오류(예외 첫 줄)
    - npe: `java.lang.NullPointerException` — 디버그 정보(`-g`)를 넣어 컴파일해 문구에 변수 이름(`because "n" is null`)이 나오게 한다. 없으면 `"<local1>"`처럼 나온다
    - idx: `java.lang.IndexOutOfBoundsException: Index 3 out of bounds for length 3`
- **컴파일·실행 헬퍼**: 16편의 파일 묶음 컴파일·실행 헬퍼를 가져오되, 이번 편은 패키지가 없으므로 `Main` 파일 하나만 컴파일·실행한다. 필요한 확장은 두 가지다.
  1. 기대한 실행 중 오류(예외 첫 줄)를 대조하는 옵션. 기존 헬퍼는 실행 중 오류가 나면 실패로만 처리한다
  2. 디버그 정보를 넣어 컴파일하는 것(NPE 문구에 변수 이름)
  - 화면의 출력·오류 콘솔은 헬퍼가 얻은 실제 결과로 그린다(직접 적지 않는다). 모든 예제는 기존처럼 예제 기록 파일에 남긴다
- **사실 표현 주의**
  - "꺾쇠 안에는 클래스 타입만"은 기본 타입을 쓸 수 없다는 뜻으로 말한다. 인터페이스·배열 타입도 들어갈 수 있으므로 화면에는 "기본 타입은 안 됨"을 함께 쓴다
  - 오토박싱·언박싱은 "자바가 자동으로 바꿔 준다"로 말하고, 캐시·`valueOf` 내부 동작은 말하지 않는다(rm 장면의 `Integer.valueOf`는 "`Integer` 객체로 만들어 값을 지운다"로만 설명한다)
  - "변수 타입은 `List`로 받는다"는 "기본적으로"로 완화한다
  - `remove(1)`은 "인덱스를 받는 `remove`가 먼저 선택된다"로 말하고, 오버로딩 선택 규칙의 세부는 다루지 않는다. 오버로딩(9편) 용어만 연결해도 된다
- **장면 구성 요소**
  - wrap은 기존 `table()` 헬퍼로 대응표를 그리고, 예외적인 두 줄(`Integer`·`Character`)을 강조한다
  - box·list는 코드 블록 아래 결과 콘솔, 오토박싱·언박싱은 화살표 칩으로 방향을 보여 준다
  - list는 배열과 리스트의 비교를 `.vs` 카드로 보여 준다(`arr[0]` ↔ `get(0)`, `.length` ↔ `size()`)
  - edit는 지우기 전·후 인덱스 표(0·1·2·3 열)로 당겨짐을 보여 준다
  - npe·idx·nums 오류는 `.warn`, nums의 `List` 타입 설명은 `.note`
  - 코드 한 줄은 33자 이하로 쓴다. `List<Integer> scores = new ArrayList<>();`처럼 긴 줄은 `=` 뒤에서 줄바꿈한다
- **대본**
  - 영어 키워드는 한글 발음으로 쓴다(래퍼 클래스, 인티저, 캐릭터, 더블, 불리언, 오토박싱, 언박싱, 파스인트, 널, 어레이리스트, 리스트, 임포트, 애드, 겟, 셋, 리무브, 컨테인즈, 사이즈, 밸류오브, 널 포인터 익셉션, 인덱스 아웃 오브 바운즈 익셉션)
  - 길이는 대본 전체를 먼저 써서 확인하고, 3분을 넘으면 음성 생성 전에 줄인다
- **정리 장면** (7줄 안팎, 대본 작성 때 확정)
  1. 래퍼 클래스: 기본 타입을 객체로(`int`→`Integer`, `char`→`Character`)
  2. 오토박싱·언박싱은 자동, `null` 언박싱은 오류
  3. `ArrayList`: `add`·`get`·`size()`, 크기는 알아서
  4. `remove`하면 뒤 칸이 당겨진다, `set`·`contains`
  5. 담을 타입은 클래스만 → `List<Integer>`
  6. 변수는 기본적으로 `List` 타입으로 받는다
  7. `remove(1)`은 1번 칸, 값은 `Integer.valueOf`
  - 마지막에 다음 편(람다식) 예고와 👍 구독 · 좋아요

## Testing Decisions

- **좋은 테스트의 기준**: 시청자가 화면에서 보는 결과를 검사한다. 즉 실제로 컴파일·실행한 예제의 출력, javac의 실제 오류 문구, 실행 중 예외의 실제 문구가 대본의 기대값과 같은지 본다. 빌드 스크립트 내부 구조나 HTML 마크업은 검사하지 않는다.
- **테스트 지점은 하나**: 16편 빌드의 컴파일·실행 대조 헬퍼를 그대로 쓰고, 실행 중 예외 대조와 디버그 정보 컴파일만 확장한다. 새 테스트 지점은 만들지 않는다.
- **대조 항목**
  - 출력 대조: wrap, box(2건), list(3건), edit(5건), nums, rm(2건)
  - 컴파일 오류 대조(1건): nums `ArrayList<int>`(첫 오류 + 설명 줄)
  - 실행 중 오류 대조(2건): npe, idx
  - 기대와 다르면(출력이 다르거나, 기대한 예외가 안 나거나, 다른 예외가 나면) 빌드를 멈춘다
- **빌드 이후 검증** (기존 절차)
  - HyperFrames check: 오류 0건, 레이아웃 겹침·넘침 없음. `line_unread` 경고는 허용한다
  - snapshot: 모든 장면을 확인하고, 가장 빽빽한 장면(edit 또는 nums)을 390px 폭으로 줄여 모바일 가독성을 확인한다
  - 자막: 대사 중 자막 없는 시간이 0초인지 확인한다
  - 렌더링 후 ffprobe: 1080×1920, 오디오 트랙 존재
- **수동 검토**: 나레이션 문장이 화면의 기대 결과와 같은지 직접 확인한다(예: "구십이가 지워져요", "합계는 이백오십오"). 자동 대조는 예제 결과까지만 하기 때문이다.
- **참고할 기존 사례**: 16편 빌드의 컴파일·실행·오류 대조 헬퍼, 3편 배열의 인덱스 오류 장면, 7편의 향상된 for 장면.

## Out of Scope

- 래퍼끼리 `==`로 비교하는 함정(-128~127 캐시)과 `equals()`
- 제네릭 문법 자체(제네릭 클래스·메소드 만들기, 와일드카드)
- `LinkedList`, `Set`, `Map` 등 다른 컬렉션과 컬렉션 프레임워크 전반
- `List.of()`의 변경 불가 리스트, `Arrays.asList()`
- `Collections.sort()`, `indexOf`, `clear`, `isEmpty`, `addAll` 등 이번에 다루지 않는 메소드
- 리스트를 도는 중에 지우는 문제(`ConcurrentModificationException`)
- 람다식, `forEach`, `removeIf`, 스트림(18·19편)
- `Integer.MAX_VALUE` 등 래퍼 클래스의 상수와 그 밖의 메소드
- 디자인·템포·제작 도구의 변경

## Further Notes

- 시리즈 순서: … → 패키지(15) → 접근 제어자(16) → 래퍼 클래스와 List(17) → 람다식(18) → 스트림(19). 처음에는 17편을 스트림으로 기획했으나, List·제네릭·람다를 아직 다루지 않아 순서를 바꿨다. 래퍼 클래스는 `List<Integer>`에 꼭 필요해 List와 한 편으로 묶었다.
- 6편 화살표 switch에서 `->`가 이미 나왔다. 18편 람다식에서 "같은 기호, 다른 뜻"이라고 짚어 줄 것(이번 편 범위 밖, 메모로만 남긴다).
- 용어 5개(래퍼 클래스, 오토박싱 / 언박싱, 리스트, ArrayList, 담을 타입)는 기획 단계에서 GLOSSARY에 등록했다.
- 기획 중 확인한 javac 오류·예외 문구는 로컬 JDK 25(영문 로케일 `-J-Duser.language=en`) 기준이다.
