# 03: 위아래 비교 레이아웃 + STEP 2 변수를 붙잡는다 · STEP 3 자바는 왜?

**What to build:** 자바스크립트와 자바 코드를 한 화면에서 비교하는 레이아웃과, 그것을 쓰는 두 장면.

- **위아래 비교 레이아웃**: 위 카드 자바스크립트, 아래 카드 자바. 2열 `.vs`는 33자 코드가 들어가지 않으므로 쓰지 않는다. 코드는 `sm`(34px). 카드마다 라벨("JavaScript"/"Java")과 결과 상자(출력 / 컴파일 오류). 라벨 색은 영상 전용 CSS에서 자바스크립트 `--blue`, 자바 `--green`(디자인 토큰은 그대로). 04도 이 레이아웃을 쓴다
- capture (진행 2): JS `let x = 1;` / `const f = () => x;` / `x = 2;` → `f()` 출력 `2` / 자바 `int x = 1;` / `Supplier<Integer> f = () -> x;` / `x = 2;` → 컴파일 오류(`effectively final`, 기존 `jce`). 자바스크립트는 변수 자체를 붙잡고, 자바는 사실상 final만 붙잡는다(19편 연결)
- why (진행 3): JLS §15.27.2가 든 이유 "계속 바뀌는 지역 변수를 붙잡으면 동시성 문제". 자바 `makeCounter`에서 `++count` → 컴파일 오류, `int[] count = {0};` / `return () -> ++count[0];`로 바꾸면 `1 2 1`(`members=`로 `static` 메소드). `.note`: 실무는 `AtomicInteger` — 22편 스레드 참고. 나레이션에서도 아토믹 인티저를 한 번 말한다
