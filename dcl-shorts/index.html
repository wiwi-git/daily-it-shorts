STEP 1 · 계정

CREATE USER

계정 = 사용자 이름 @ 호스트

CREATE USER 'app'@'localhost'
IDENTIFIED BY 'app_pw';
만든 계정 →app@localhost
'localhost' = 같은 서버에서 접속'%' = 모든 호스트 · 꼭 필요할 때만
STEP 2 · GRANT

GRANT

무슨 권한을 · 어디에 · 누구에게

SHOW GRANTS
FOR 'app'@'localhost';
만든 직후 →USAGE ON *.* (전역 권한 없음)
GRANT SELECT, INSERT ON shop.*
TO 'app'@'localhost';
SHOW GRANTS
FOR 'app'@'localhost';
GRANT 후 →USAGE ON *.* (전역 권한 없음)SELECT, INSERT ON shop.*

STEP 3 · 권한 없음

거절되는 작업

report = SELECT만

CREATE USER 'report'@'localhost'
IDENTIFIED BY 'report_pw';
GRANT SELECT ON shop.products
TO 'report'@'localhost';
report 계정으로 접속해서
DELETE FROM products
WHERE id = 2;
⚠ ERROR 1142
DELETE command denied to user 'report'@'localhost'
STEP 4 · REVOKE

REVOKE

GRANT와 같은 모양 · TO → FROM

REVOKE INSERT ON shop.*
FROM 'app'@'localhost';
SHOW GRANTS
FOR 'app'@'localhost';
REVOKE 후 →USAGE ON *.* (전역 권한 없음)SELECT ON shop.*

모든 개발자에게 루트 계정을 줘도 될까요?
계정을 만들고, 권한을 주고 뺏는 DCL,
한 번에 정리해 드립니다.
DCL은 데이터 제어어.
누가, 어떤 데이터에,
무엇을 할 수 있는지를 정합니다.
핵심은 꼭 필요한 권한만
주는 최소 권한 원칙이에요.
먼저 크리에이트 유저로 계정을 만듭니다.
마이에스큐엘 계정은 사용자 이름과
접속 위치인 호스트가 한 쌍이에요.
로컬호스트는 같은 서버에서 접속할 때,
퍼센트는 모든 호스트와 매칭되니
꼭 필요할 때만 쓰세요.
막 만든 계정은 아무 권한이 없어요.
그랜트로 무슨 권한을, 어디에,
누구에게 줄지 적습니다.
쇼 그랜츠로 확인하면
셀렉트와 인서트가 보이죠.
맨 위의 유세이지는 서버 전체에
대한 권한은 없다는 표시예요.
온 뒤에는 범위를 적어요.
별 점 별은 서버 전체,
숍 점 별은 숍 데이터베이스의 모든 테이블,
숍 점 프로덕츠는 테이블 하나만입니다.
조회만 하는 리포트 계정에는 프로덕츠
테이블의 셀렉트만 줘 볼게요.
이 계정으로 딜리트를 실행하면,
권한이 없다는 에러로 거절됩니다.
준 권한을 회수할 때는 리보크.
그랜트와 같은 모양에
투 대신 프롬을 씁니다.
인서트를 회수하면,
앱 계정에는 셀렉트만 남아요.
안 쓰는 계정은 드롭 유저로 지우세요.
그리고 앱에는 루트 대신 전용 계정을,
권한은 필요한 데이터베이스에 필요한 만큼만.
이게 최소 권한 원칙입니다.
정리하면, 크리에이트 유저로 계정을 만들고,
그랜트로 권한을 주고,
쇼 그랜츠로 확인, 리보크로 회수,
드롭 유저로 삭제.
권한은 필요한 만큼만!
도움이 됐다면 구독과 좋아요 부탁드립니다!
