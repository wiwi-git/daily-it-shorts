STEP 4-2 · 클래스

클래스에는 둘만

파일에 바로 쓰는 클래스: public · 기본

public class Student { }
class Desk { }
private class Club { }
컴파일 오류
modifier private not allowed here

STEP 5 · 캡슐화

왜 private 으로 숨길까?

잘못된 값을 막는다

📄 school/Student.java
private int score;
public int getScore() { ... }
public void setScore(int v) {
if (v >= 0 && v <= 100)
score = v;
}
s.setScore(-5) → s.getScore()
85
📄 app/Main.java
s.score = -5;
컴파일 오류
score has private access in Student
캡슐화 = private + getter · setter
STEP 5-1 · 오버라이딩

범위를 좁힐 수 없다

public → 기본 오류 · 넓히기는 OK

📄 school/Teacher.java
public class Teacher
extends Person {
@Override
void hello() { ... }
}
컴파일 오류
hello() in Teacher cannot override hello() in Person
attempting to assign weaker access privileges; was public
좁히기public → 기본 ❌
넓히기protected → public ✅
그래서 인터페이스 메소드를 구현할 때
public 이 필수였다 (13편)
정리

접근 제어자 6가지

1private → 같은 클래스만
2기본 → 같은 패키지까지
3protected → +다른 패키지 자식
4public → 어디서나
5필드는 private + getter·setter
6오버라이딩: 범위 좁히기 ❌
