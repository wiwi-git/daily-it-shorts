자바 상속 정리
JAVA 입문 · 열 번째

클래스의
상속

extends · super
STEP 1 · 중복 코드

똑같은 코드가 반복

name · hello() 가 두 클래스에 중복

class Student {
String name;
int score;
void hello() { … }
}
class Teacher {
String name;
String subject;
void hello() { … }
}
클래스가 늘수록 복사도 늘어요
STEP 1 · extends

공통 부분은 부모로

extends 부모이름 으로 물려받기

class Person {
String name;
void hello() { … }
}
class Student extends Person {
int score;
}
class Teacher extends Person {
String subject;
}
물려주는 쪽 = 부모 클래스 · 받는 쪽 = 자식 클래스
STEP 2 · 물려받은 것 쓰기

자식 객체로 부모 것 사용

Student 안에 hello() 가 없어도 호출

Student s1 = new Student();
s1.name = "민수";
s1.score = 85;
s1.hello();
실행 결과 (Person 의 hello)
민수 안녕
Studentname · hello() 물려받음+ 자기 필드 score
Teachername · hello() 물려받음+ 자기 필드 subject
STEP 3 · 오버라이딩

같은 hello(), 다른 결과

물려받은 메소드를 다시 정의(재정의)

class Student extends Person {
void hello() {
System.out.println(
"학생 " + name + " 안녕");
}
}
class Teacher extends Person {
void hello() {
System.out.println(
name + " 선생님 안녕");
}
}
실행 결과
학생 민수 안녕
서준 선생님 안녕
STEP 3 · 오버라이딩

@Override 와 비교

오버라이딩 ≠ 오버로딩

class Student extends Person {
@Override
void hello() { … }
}
@Override = 진짜 오버라이딩인지 컴파일러가 확인
오버로딩같은 클래스이름 같고 매개변수 다름
오버라이딩자식 클래스이름·매개변수 같고 내용만 다시
STEP 4 · super()

부모 생성자 호출

자식 생성자 첫 줄의 super(name)

class Person {
Person(String name) {
System.out.println("부모 생성자");
this.name = name;
}
}
class Student extends Person {
int score;
Student(String name,
int score) {
super(name);
System.out.println("자식 생성자");
this.score = score;
}
}
STEP 4 · 실행 순서

부모가 먼저, 자식이 다음

생성자마다 출력문을 넣어 확인

new Student("민수", 85);
실행 결과
부모 생성자
자식 생성자
① 부모 생성자Person(name) 먼저
② 자식 생성자Student 가 다음
STEP 4-1 · 주의

super() 가 없으면?

부모의 기본 생성자를 찾다가 실패

class Student extends Person {
int score;
Student(String name,
int score) {
// super(name); 없음
this.score = score;
}
}
컴파일 오류
constructor Person in class Person cannot be applied to given types;
지난 시간: 생성자를 만들면 기본 생성자가 없다 → Person() 없음
STEP 5 · super.메소드()

부모 버전도 함께

오버라이딩 안에서 super.hello()

s1.hello();
실행 결과
민수 안녕
점수 85
super(name);부모 생성자 호출생성자 첫 줄
super.hello();부모 메소드 호출메소드 안
STEP 5-1 · 주의

부모 클래스는 하나만

extends 뒤에는 클래스 하나

class Student extends
Person, Teacher {
int score;
}
컴파일 오류
'{' expected
부모를 둘 적으면 컴파일 오류
정리

상속 6가지

1extends = 부모를 물려받기
2부모의 필드·메소드를 바로 사용
3오버라이딩 = 다시 정의
4super() = 부모 생성자 먼저 호출
5super.메소드() = 부모 메소드
6부모 클래스는 하나만

자바 입문 열 번째, 클래스의 상속!
같은 코드를 반복해서 쓰지 않게 해
주는 부모 클래스와 자식 클래스, 오버라이딩,
슈퍼까지 정리해 드립니다.
지난 시간의 스튜던트와
티처 클래스를 볼게요.
둘 다 네임 필드와 헬로
메소드가 똑같이 들어 있어요.
클래스가 늘어날수록 같은
코드를 계속 복사해야 하죠.
공통 부분은 퍼슨 클래스로 빼내요.
그리고 클래스 이름 뒤에
익스텐즈 퍼슨을 붙이면,
부모가 자식에게 물려주듯 스튜던트와
티처가 퍼슨의 필드와 메소드를 물려받아요.
물려주는 쪽이 부모 클래스,
받는 쪽이 자식 클래스예요.
스튜던트 안에는 헬로가 없는데도,
에스 원 닷 헬로를 부르면
민수 안녕이 출력돼요.
부모의 메소드를 물려받았기 때문이에요.
네임 필드도 물려받아서
점을 찍어 쓸 수 있어요.
자식은 자기만의 필드도 더할 수 있어요.
스튜던트는 스코어,
티처는 서브젝트를 더 가져요.
그런데 자식마다 헬로를 다르게 하고 싶다면?
자식 클래스에서 물려받은
메소드를 같은 이름,
같은 매개변수로 다시 정의하면 돼요.
이것을 오버라이딩,
재정의라고 해요.
같은 헬로를 불러도,
스튜던트는 학생 민수 안녕,
티처는 서준 선생님 안녕이 나와요.
메소드 위에 골뱅이 오버라이드를 붙이면,
진짜 오버라이딩이 맞는지 컴파일러에게
확인을 맡길 수 있어요.
지난 시간의 오버로딩과 헷갈리기 쉬운데요,
오버로딩은 같은 클래스에서
이름은 같고 매개변수가 다른 것,
오버라이딩은 자식 클래스에서 이름과
매개변수가 같고 내용만 다시 쓰는 거예요.
이번엔 생성자예요.
퍼슨에 네임을 받는 생성자를 만들고,
스튜던트 생성자 첫 줄에서 슈퍼 괄호
네임으로 부모 생성자를 호출해요.
두 생성자에는 확인용
출력문을 하나씩 넣었어요.
뉴 스튜던트로 객체를 만들면,
부모 생성자의 출력이 먼저,
자식 생성자의 출력이 다음에 나와요.
부모 부분을 먼저 만든 뒤에
자식을 완성하기 때문에,
부모 생성자가 항상 먼저 실행돼요.
주의할 점!
슈퍼 네임을 지우면 컴파일 오류가 나요.
슈퍼를 쓰지 않으면 자바가
부모의 기본 생성자를 부르는데,
퍼슨은 생성자를 직접 만들어서
기본 생성자가 없기 때문이에요.
지난 시간에 배운,
생성자를 직접 만들면 기본 생성자가
생기지 않는다는 내용이죠.
슈퍼는 메소드에도 써요.

생성자를 부르는 슈퍼 괄호와,

메소드는 서로 다른 쓰임이에요.
