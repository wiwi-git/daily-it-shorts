람다식

s -> s >= 80
매개변수 → 몸체클래스 없이 한 줄
STEP 1 · 왜 필요한가

클래스 대신 한 줄

구현 클래스 → 람다식

interface Checker { boolean check(int s); }
class Pass implements Checker {
public boolean check(int s) {
return s >= 80;
}
}
Checker c = new Pass();
Checker c = s -> s >= 80;
c.check(85) · c.check(78)
true false
STEP 2 · 문법

세 부분으로 읽기

매개변수 -> 몸체

(int s)매개변수
->화살표
{ return s >= 80; }몸체
-> 는 화살표
화살표 switch 와 기호만 같고 뜻은 다르다
STEP 2-1 · 줄여 쓰기

더 짧게

타입 · 괄호 · { return ; } 생략

모두 같은 람다식
(int s) -> { return s >= 80; }
(s) -> { return s >= 80; }
s -> { return s >= 80; }
s -> s >= 80
s←매개변수가 하나면 괄호 생략
매개변수 0개 · 2개면 괄호 필수
() -> 80 · (a, b) -> b - a
STEP 3 · 함수형 인터페이스

추상 메소드는 하나만

두 개면 람다식 불가

interface Checker {
boolean check(int s);
boolean ok(int s); // 추가
}
Checker c = s -> s >= 80;
컴파일 오류
incompatible types: Checker is not a functional interface
multiple non-overriding abstract methods found in interface Checker
추상 메소드가 딱 하나 = 함수형 인터페이스
@FunctionalInterface 를 붙이면
인터페이스 선언에서 바로 오류
Unexpected @FunctionalInterface annotation
STEP 3-1 · Predicate

자바가 만들어 둔 것

Predicate = 검사용 함수형 인터페이스

import java.util.function.Predicate;
Predicate<Integer> p =
s -> s >= 80;
p.test(85); // true
직접 만든Checkercheck()
자바가 만든Predicatetest()
STEP 4 · forEach

하나씩 꺼내 실행

값마다 람다식을 실행

List<String> names =
new ArrayList<>();
names.add("민수");
names.add("서준");
names.add("지우");
names.forEach(n ->
System.out.println(n));

STEP 4-1 · removeIf

조건으로 지우기

람다식 = 지울 조건

List<Integer> scores =
new ArrayList<>();
scores.add(85);
scores.add(92);
scores.add(78);
scores.removeIf(s -> s < 80);
// scores → [85, 92]
지우기 전859278
지운 뒤8592
STEP 4-2 · sort

람다식으로 정렬

두 값을 비교 → 괄호 필수

List<Integer> scores =
new ArrayList<>();
scores.add(85);
scores.add(92);
scores.add(78);
scores.sort((a, b) -> b - a);
// scores → [92, 85, 78]
정렬 뒤928578
b - a → 큰 순서
a - b → 작은 순서
아주 큰 수까지 안전하게: Integer.compare(b, a)
STEP 5 · 사실상 final

람다식 안에서 더하기?

람다식에서 쓰는 지역 변수는 다시 대입 ✗

// scores = [85, 92, 78]
int sum = 0;
scores.forEach(s -> sum += s);
컴파일 오류
local variables referenced from a lambda expression must be final or effectively final
한 번도 다시 대입 안 하는 변수
= 사실상 final → 람다식에서 OK
합계는 향상된 for 로
int sum = 0;
for (int s : scores) sum += s;
// sum → 255
