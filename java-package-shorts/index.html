자바 입문 패키지 정리
JAVA 입문 · 열다섯 번째

패키지

package · import
STEP 1 · package 선언

클래스를 묶는 이름

패키지 이름 = 폴더와 맞춘다

📄 school/Student.java
package school;
 
public class Student
extends Person { ... }
school/
├─ Person.java
├─ Student.java
└─ Teacher.java
app/
└─ Main.java
실무에서는 도메인을 거꾸로
com.example.school
STEP 2 · 전체 이름

school.Student

전체 이름 (패키지 이름 + 클래스 이름)

📄 app/Main.java
package app;
 
school.Student s =
new school.Student(
"민수", 85);
s.hello();
실행 결과
학생 민수 안녕
STEP 2-1 · import

import 로 줄여 쓰기

이름만 줄여 쓰게 해 준다

📄 app/Main.java
package app;
import school.Student;
 
Student s = new Student(
"민수", 85);
s.hello();
실행 결과
학생 민수 안녕
클래스를 복사하는 것이 아니다
이름을 줄여 쓰게 해 줄 뿐
STEP 3 · public 필요

public 이 없으면?

다른 패키지에서 쓰려면 public

📄 school/Student.java
class Student extends Person
컴파일 오류
Student is not public in school; cannot be accessed from outside package
public 이 없으면 같은 패키지에서만
public class Student
extends Person {
public Student(String name,
int score) { ... }
public void hello() { ... }
}
public 클래스 = 파일 이름 .java
STEP 4 · 표준 라이브러리

java.util.Arrays

자바가 만든 클래스도 패키지에

import java.util.Arrays;
 
int[] scores = {85, 90, 70};
Arrays.sort(scores);
System.out.println(
Arrays.toString(scores));
실행 결과
[70, 85, 90]
import java.util.*;
→ 그 패키지의 public 클래스 모두
하위 패키지는 포함 안 됨
STEP 4-1 · java.lang

import 없이 쓰는 것

java.lang 은 자동 import

java.lang.Stringjava.lang.System
java.lang.String name =
"민수";
System.out.println(name);
실행 결과
민수
String = java.lang.String
짧게 써도, 전체 이름으로 써도 같다
STEP 5 · 같은 이름 클래스

Date 가 두 개?

하나는 전체 이름으로

import java.util.Date;
import java.sql.Date;
컴파일 오류
a type with the same simple name is already defined by the single-type-import of Date
import java.util.Date;
 
Date now = new Date();
java.sql.Date day =
java.sql.Date.valueOf(
"2026-11-16");
System.out.println(day);
실행 결과
2026-11-16
정리

패키지 6가지

1package 로 묶고 폴더와 맞춤
2전체 이름 = 패키지 + 클래스
3import 로 이름 줄여 쓰기
4다른 패키지 클래스 → public
5java.lang 은 import 없이
6같은 이름 → 하나는 전체 이름

이것을 전체 이름이라고 해요.

매번 길게 쓰긴 번거롭죠.
위에 임포트 스쿨 닷 스튜던트를 적으면,
스튜던트만 써도 돼요.
결과는 똑같이 학생 민수 안녕이에요.
임포트는 클래스를 복사하는 게 아니라,
이름을 줄여 쓰게 해 줄 뿐이에요.
그런데 스튜던트 클래스에 퍼블릭이
없으면 컴파일 오류가 나요.
퍼블릭이 없으면 같은 패키지
안에서만 쓸 수 있거든요.
지금처럼 다른 패키지의 메인에서
객체를 만들고 메소드를 부르려면,
생성자와 메소드도 퍼블릭이어야 해요.
자세한 건 다음 편 접근
제어자에서 다룰게요.
그리고 퍼블릭 클래스는
파일 이름과 같아야 해요.
자바가 미리 만들어 둔 클래스도
패키지로 묶여 있어요.
자바 유틸 패키지의 어레이즈를

90 순서로 나와요.
별표를 쓰면 그 패키지의 퍼블릭 클래스를

단, 하위 패키지는 포함되지 않아요.
그럼 스트링과 시스템은

자바 랭 패키지는 자동으로
임포트되기 때문이에요.
자바 닷 랭 닷 스트링으로

이름이 같은 클래스도 있어요.
자바 유틸과 자바 에스큐엘에

다른 하나는 전체 이름으로 써요.
