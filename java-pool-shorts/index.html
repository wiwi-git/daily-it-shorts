STEP 2 · 작업 맡기기

submit()

스레드 2개짜리 풀에 작업을 맡긴다

import java.util.concurrent.*;
try (ExecutorService pool =
Executors.newFixedThreadPool(2)
) {
pool.submit(() ->
System.out.println("민수 85"));
pool.submit(() ->
System.out.println("서준 92"));
}
실행 결과 예시
민수 85
서준 92

STEP 3 · 값 돌려받기

Future · get()

값을 돌려주는 작업 = Callable

main(…) throws Exception get()도 예외를 던질 수 있어서
try (ExecutorService pool =
Executors.newFixedThreadPool(2)
) {
Future<Integer> f1 =
pool.submit(() -> 85);
Future<Integer> f2 =
pool.submit(() -> 92);
int sum = f1.get() + f2.get();
System.out.println(sum);
}

스레드 풀

4get()은 끝날 때까지 기다림
5try-with-resources로 닫기

스레드도 만들고 없애는 데 시간이 들어요.
그리고 작업마다 새로 만들면,
작업이 천 개일 때 스레드도 천 개가 돼요.
스레드 풀은 정해 둔
개수까지만 스레드를 만들고,
그 스레드들에 작업을 차례로 맡겨요.

남은 작업은 대기 줄에서 기다리다가,

스레드 풀에 2를 넣으면,
스레드 두 개짜리 풀이 만들어져요.
타입은 익스큐터 서비스예요.
할 일은 이십이 편처럼 람다식으로 쓰고,
뉴 스레드 대신 풀의 서브밋에 넘겨요.
이렇게 풀에 맡기는 코드
한 덩어리를 작업이라고 해요.
스타트를 부르지 않아도 풀의
스레드가 알아서 실행해요.
이번 실행에서는 민수가 먼저 나왔지만,
순서는 실행할 때마다 달라질 수 있어요.
이번엔 작업이 점수를
출력하지 않고 돌려주게 해 볼게요.
람다식이 팔십오를 돌려주면,
서브밋은 바로 퓨처를 돌려줘요.

이렇게 값을 돌려주는

겟도 예외를 던질 수 있어서,
메인에 스로우즈 익셉션을 붙여요.
이제 트라이 괄호를 볼게요.
파일을 닫을 때 쓴 트라이 위드 리소스예요.
블록이 끝나면, 풀은 작업이 모두 끝날
