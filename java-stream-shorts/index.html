STEP 1 · 원본은 그대로

removeIf vs filter

스트림은 원본 리스트를 바꾸지 않는다

지난 편 removeIf = 지울 조건
List<Integer> scores =
new ArrayList<>();
scores.add(85);
scores.add(92);
scores.add(78);
scores.removeIf(s -> s < 80);
// scores → [85, 92]
removeIf 뒤 scores859278
스트림 filter (새 scores = [85, 92, 78])
List<Integer> pass =
scores.stream()
.filter(s -> s >= 80)
.toList();
// pass → [85, 92]
// scores → [85, 92, 78]
STEP 2 · 스트림 3단계

만들기 → 중간 → 최종

최종 연산에서 결과가 나온다

scores.stream()만들기
.filter(s -> s >= 80)중간 연산
.toList();최종 연산
결과
[85, 92]
toList() 는 자바 16부터
그 전: .collect(Collectors.toList())
STEP 2-1 · map

값을 바꾸기

map = 값을 다른 값으로

List<String> result =
names.stream()
.map(n -> n + "님")
.toList();
// result → [민수님, 서준님, 지우님]
names민수서준지우
map 뒤민수님서준님지우님
filter거르기개수가 줄 수 있다
map바꾸기개수는 그대로
STEP 3 · 이어 붙이기

중간 연산 여러 개

거르고 → 바꾸고 → 모으기

List<Integer> bonus =
scores.stream()
.filter(s -> s >= 80)
.map(s -> s + 5)
.toList();
// bonus → [90, 97]
결과9097
중간 연산 filter · map최종 연산 toList
중간 연산은
최종 연산을 불러야 실행된다
STEP 3-1 · sorted

스트림으로 정렬

sorted() = 오름차순

List<Integer> asc =
scores.stream()
.sorted()
.toList();
// asc → [78, 85, 92]
오름차순788592
내림차순: 지난 편 sort 와 같은 람다식
List<Integer> desc =
scores.stream()
.sorted((a, b) -> b - a)
.toList();
// desc → [92, 85, 78]
내림차순928578
아주 큰 수까지 안전하게: Integer.compare(b, a)
STEP 4 · count · sum

개수와 합계

최종 연산은 숫자로도

long cnt =
scores.stream()
.filter(s -> s >= 80)
.count();
// cnt → 2
합계: 지난 편엔 향상된 for 로 255
int sum =
scores.stream()
.mapToInt(s -> s)
.sum();
// sum → 255
mapToInt(s -> s)
Integer → int (언박싱) 숫자 전용 스트림
STEP 5 · 한 번만 쓴다

스트림 다시 쓰기?

최종 연산을 한 스트림은 다시 못 쓴다

import java.util.stream.Stream;
Stream<Integer> st =
scores.stream();
System.out.println(st.count());
System.out.println(st.count());
실행 결과
3
실행 오류
java.lang.IllegalStateException:
stream has already been operated upon or closed
다시 쓰려면 새로 만들기
st = scores.stream();
st.count(); // 3
