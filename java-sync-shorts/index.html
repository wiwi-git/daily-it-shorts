지난 편 synchronized의 문제

지난 편메소드 전체에
synchronized
오늘필요한 줄만 ·
AtomicInteger
STEP 1 · 메소드 전체를 잠그면

지난 편 코드

synchronized가 만 번 도는 메소드 전체에

static int count = 0;
static synchronized void inc() {
for (int i = 0; i < 10000; i++)
count++;
}
시간 →
스레드 1
inc() 만 번
스레드 2
기다림inc() 만 번
실행 결과 · 20회 모두
20000
결과는 맞지만
사실상 차례로 실행
STEP 2 · 동기화 블록

필요한 줄만

synchronized (잠금 객체) { 이 줄만 }

static int count = 0;
static final Object lock =
new Object();
static void inc() {
for (int i = 0; i < 10000; i++)
synchronized (lock) {
count++;
}
}
실행 결과 · 20회 모두
20000
같은 잠금 객체
두 스레드가 함께 쓰는 static 필드
잠그는 범위는 필요한 만큼만
STEP 3 · AtomicInteger

한 번에 끝내기

incrementAndGet() · 값은 get()

import java.util.concurrent.atomic.*;
static AtomicInteger count =
new AtomicInteger();
static void inc() {
for (int i = 0; i < 10000; i++)
count.incrementAndGet();
}
// main에서: a·b start·join 뒤
System.out.println(count.get());
실행 결과 · 20회 모두
20000
읽기→더하기→쓰기 한 번에 원자적 연산 (쪼개지지 않는)
synchronized 없이끼어들기 불가
STEP 4 · 스레드 안전 리스트

ArrayList도?

두 스레드가 만 번씩 add

import java.util.*;
static List<Integer> list =
new ArrayList<>();
static void add() {
for (int i = 0; i < 10000; i++)
list.add(i);
}
실행 결과 예시 · 매번 다름
14302
값이 빠지거나
예외가 나기도
static List<Integer> list =
Collections.synchronizedList(
new ArrayList<>());
실행 결과 · 20회 모두
20000
스레드 안전
여러 스레드가 함께 써도 올바른 결과

👍 구독 · 좋아요
자바 입문 스물세 번째,
동기화 더 깊이!
지난 편에서는 메소드에 싱크로나이즈드를
붙여서 경쟁 조건을 막고,
항상 이만을 만들었어요.
결과는 맞았지만,
사실 문제가 하나 있었어요.
오늘은 잠그는 범위를 좁히는 법과,
싱크로나이즈드 없이 푸는 법을 알아볼게요.
지난 편 코드를 다시 볼게요.
싱크로나이즈드가 만 번 도는
메소드 전체에 붙어 있어요.
그래서 한 스레드가 들어가면,
만 번을 다 끝낼 때까지 다른
스레드는 들어가지 못하고 기다려요.
결과는 항상 이만이지만,
두 스레드가 사실상 차례로 실행된 거예요.
이러면 스레드를 나눈 의미가 줄어요.
필요한 줄만 잠그려면
싱크로나이즈드 블록을 써요.
먼저 잠금 객체로 쓸 오브젝트를
스태틱 파이널 필드로 하나 만들어요.
그리고 카운트 플러스 플러스 한 줄만,
싱크로나이즈드 괄호 안에
잠금 객체를 넣어 감싸요.
이제 한 번에 한 스레드만
이 블록에 들어가고,
결과는 항상 이만이에요.
두 스레드가 꼭 같은 잠금
객체를 써야 서로 막아 줘요.
잠그는 범위는 필요한 만큼만
좁히는 게 원칙이에요.
카운터라면 더 간단한 방법이 있어요.
인트 대신 아토믹 인티저를 쓰고,
플러스 플러스 대신
인크리먼트 앤 겟을 불러요.
카운트 플러스 플러스는 읽기, 더하기,
쓰기 세 단계라서 값이 사라졌죠.
인크리먼트 앤 겟은 이 세 단계를
한 번에 끝내는 원자적 연산이라,
중간에 다른 스레드가 끼어들 수 없어요.
싱크로나이즈드 없이도 항상 이만이고,
값은 겟으로 꺼내요.
변수만 그런 게 아니에요.
어레이 리스트에 두 스레드가
만 번씩 애드하면,
크기가 이만보다 적게 나오고,
실행할 때마다 달라요.
값이 빠지기도 하고,
예외가 나기도 해요.
어레이 리스트는 스레드 안전하지 않거든요.
컬렉션스 점 싱크로나이즈드 리스트로 감싸면,
여러 스레드가 함께 애드해도
항상 이만이 나와요.
이렇게 여러 스레드가 함께 써도 올바른
결과를 내는 걸 스레드 안전이라고 해요.
정리할게요.
메소드 전체를 잠그면
사실상 차례로 실행돼요.
싱크로나이즈드 블록으로 필요한 줄만 잠그고,
같은 잠금 객체를 써야 해요.
아토믹 인티저의 인크리먼트
앤 겟은 원자적 연산이에요.
어레이 리스트는 스레드 안전하지 않으니,
싱크로나이즈드 리스트로 감싸요.
구독과 좋아요 부탁드려요!
