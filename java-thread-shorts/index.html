STEP 3 · 경쟁 조건

같은 변수를 함께

만 번씩 두 번 → 20000이 아니다?

static int count = 0;
static void inc() {
for (int i = 0; i < 10000; i++)
count++;
}
 
Thread a = new Thread(Main::inc);
Thread b = new Thread(Main::inc);
a.start(); b.start();
a.join(); b.join();
System.out.println(count);
실행 결과 예시 · 매번 다름
13426
count++ 읽기→더하기→쓰기 같은 값을 읽고 각자 쓰면 → 하나 사라짐
경쟁 조건 (레이스 컨디션)

자바 입문 스물두 번째, 스레드!
스레드는 코드를 실행하는 흐름 하나예요.
지금까지 만든 프로그램은 모두,
메인 스레드 하나가 메인 메소드를
위에서 아래로 실행했어요.
스레드를 여러 개 만들면,
여러 일을 동시에 실행되는
것처럼 번갈아 처리할 수 있어요.
스레드를 만들 때는 뉴 스레드에
람다식으로 할 일을 넘겨요.
민수 팔십오를 출력하는 스레드와 서준
구십이를 출력하는 스레드를 만들고,
스타트를 부르면 각자 실행을 시작해요.
이번 실행에서는 메인 끝이 중간에 끼었어요.
메인 스레드는 다른 스레드를
기다리지 않고 자기 일을 계속하거든요.
출력 순서는 보장되지 않아서,
실행할 때마다 달라질 수 있어요.
함정 하나!
스타트 대신 런을 부르면 어떻게 될까요?
스레드 안에서 겟 네임으로 지금
실행 중인 스레드의 이름을 출력해 보면,
스타트는 스레드 영,
런은 메인이 나와요.
런을 직접 부르면 오류는 아니지만,
새 스레드 없이 메인 스레드가
그냥 메소드를 호출할 뿐이에요.
스레드가 끝날 때까지
기다리려면 조인을 써요.
슬립 천은 일 초 쉬는 거예요.
조인이 없으면 채점 끝이 먼저 나오고,
일 초 뒤에 민수 팔십오가 나와요.
티 점 조인 한 줄을 넣으면
메인 스레드가 기다려서,
민수 팔십오 다음에 채점 끝이 나와요.
슬립과 조인은 체크 예외인
인터럽티드 익셉션을 던질 수 있어서,
스레드 안에서는 트라이 캐치로 감싸고,
메인에는 쓰로우즈를 붙여요.
이번엔 두 스레드가 같은
변수를 바꿔 볼게요.
각 스레드가 카운트 플러스
플러스를 만 번씩 하면,
이만이 나와야 하죠.
그런데 실행해 보면 대부분
이만보다 적게 나오고,
실행할 때마다 달라요.
카운트 플러스 플러스는 읽고, 더하고,
쓰는 세 단계라서,
두 스레드가 같은 값을 읽고
각자 쓰면 하나가 사라져요.
이런 문제를 경쟁 조건이라고 해요.
고치는 방법은 동기화예요.
카운트를 올리는 메소드에
싱크로나이즈드를 붙이면,
한 번에 한 스레드만
그 메소드에 들어갈 수 있어요.
이제 몇 번을 실행해도 항상 이만이에요.
정리할게요.
뉴 스레드에 람다를
넘기고 스타트로 실행해요.
런을 직접 부르면 그냥 메소드 호출이에요.
출력 순서는 보장되지 않아요.
조인은 끝날 때까지 기다려요.
같은 변수를 함께 바꾸면 경쟁 조건,
싱크로나이즈드로 한 번에 하나씩.
구독과 좋아요 부탁드려요!
